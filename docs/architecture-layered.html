MVP 三层怎么定的：红= 最小可对话（C1–C12：接一句话 → agent 调工具 → 流式回复，历史可存）； 黄= 最小可干活（C13–C15：多节点工作流 + 产物契约 + 上下文注入）； 绿= 全能力（C16–C28：长程任务 + 自进化 + 评估 + 其它通道）。 判据是运行时必要性而非 import 闭包 —— 实测闭包会把 32/36 个包都算进红色 （interfaces/api 与 kernel/agent 传递 import 几乎全仓），无法区分层级。 红层是「能力归属标注」，不是可裁剪部署单元：红层包对非红层的实测 import 仍有 118 次 （最重的一条是 interfaces/api → apps/goal 14 次），所以别把红色读成「可删」。 2026-11-17 修订：kernel/session 由绿改红 —— R-014 下沉后它是会话域真身（承载 C8 历史持久化， 红层主链路 interfaces/api → kernel/session 29 次 import）。判定依据见 docs/design/mvp-tier-revision-20261117.md。
