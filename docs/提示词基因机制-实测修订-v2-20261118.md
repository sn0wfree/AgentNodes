# 提示词「基因序列」机制 · 实测修订（v2）

> 快照 2026-11-18。本文档是**框架草案的实测修订版**，用 SPDeconstruction 已切好的 5526 条条款（15 家厂商）+ 上一轮的 26 家 × 23 维矩阵交叉验证。
> 脚本：`/workspace/research/exp1…exp11_*.py`、`allele_lib.py`；数据：`allele_axis.json`。

---

## 0. 一句话

机制不是「一条 prompt → 一串等位」的线性编码，而是**三层带不同性质的结构**：

| 层 | 承载什么 | 实测性质 |
|---|---|---|
| **L1 位点存在性** | 共识骨架 | **高度趋同**：23 个位点里 18 个几乎人人共有，26 家压成 23 种图案 |
| **L2 等位取值** | 个体特征 | **整体接近随机**（比值 0.93），但**按维度分裂成两类** |
| **L3 跨厂商关系** | 家族 / 档位 | 只在 **L1 层**成立；**L2 层不能用来聚类** |

★ 本轮最重要的发现：**每个维度带一个「等位趋同比值」，它决定该维度上的跨厂商等位比较有没有意义。** T0 底线 5 个维度 **100% 是互斥型，零例外**。

## 2. L1 层：位点存在性 —— 共识骨架

### 2.1 结构是「核心 18 + 可选 5」，没有梯度

| 层 | 位点数 | 支持度 | 成员 |
|---|---|---|---|
| **核心** | 18 | 17–25 家 | 身份与角色锚定 · 输出格式规范 · 代码与工程操作 · 规划与任务分解 · 上下文与记忆 · 语气与文风 · 语言本地化 · 网络与检索 · 自主性与持续推进 · 拒答与安全策略 · 引用与来源 · 工具调用纪律 · 多模态与视觉 · 诚实与不确定性 · 错误与能力边界 · 环境与可及边界 · 权限与升级请求 · 隐私与数据 |
| **可选** | 5 | 3–10 家 | 危险类别枚举(3) · 专业免责声明(3) · 注入防御与不可信输入(6) · 中立与平衡(8) · 未成年人保护(10) |

**共识序 = 支持度降序**（可复算，单调）：
`身份与角色锚定(25) → 输出格式规范(25) → 代码与工程操作(25) → 规划与任务分解(24) → 上下文与记忆(24) → 语气与文风(23) → 语言本地化(23) → 网络与检索(21) → 自主性与持续推进(20) → 拒答与安全策略(20) → 引用与来源(19) → 工具调用纪律(19) → 多模态与视觉(19) → 诚实与不确定性(19) → 错误与能力边界(18) → 环境与可及边界(17) → 权限与升级请求(17) → 隐私与数据(15) → 未成年人保护(10) → 中立与平衡(8) → 注入防御与不可信输入(6) → 危险类别枚举(3) → 专业免责声明(3)`

★ **这替代上一轮的「证据门控 + 成对先后归一 + 相邻交换修复」**——那一套是为「自由文本条款的先后」设计的，存在集不需要，直接按支持度排。

⇒ **同图案厂商在存在性层面完全不可区分。** 存在性只够定义「档位」，不够定义「个体」。

## 3. L2 层：等位取值 —— 个体特征，且按维度分裂

### 3.1 等位键的定义

每个等位 = `受控动词 | 否定位 | 显式模态 | 条件位`。
- 受控动词：去否定 → 词干化 → 映射到 ~90 词表（`allele_lib.py`）
- 否定位：`N` / `P`（原句里就有 `not` / `never`）
- 显式模态：`must` / `should` / `may` / `can` / `will` / `must not` / `cannot` …，**空 = 散文**（SPDeconstruction 的 `D` 字段已抽好）
- 条件位：`C` / `-`（`C` 字段：scopes / triggers / exceptions）

### 3.2 等位确实提供存在性给不出的区分力

- 存在性上 **ANTHROPIC ~ OPENAI 相似度 0.913**（几乎分不开）
- 等位上这两家 **23 个维度全部不同**

⇒ **存在性定义家族，等位定义个体。**

### 3.3 ★ 等位趋同比值：第三条轴（本轮的核心发现）

**定义**（无抽样，用解析期望）：
```
某维度上，把所有厂商的等位并成词表 V_d
期望共享(a,b) = |A_a| × |A_b| / |V_d|
比值 = 实测共享 / 期望共享
```
- **> 1.25 趋同型**：厂商在这维用同一批等位（套话）
- **0.75–1.25 中性**
- **< 0.75 互斥型**：厂商在这维刻意用不同等位（法律立场 / 产品定位定制）

**结果：整体比值 0.93，平均私有等位占比 72%。**

### 3.4 ★ 零例外的规律

| tier | 趋同型 | 中性 | 互斥型 |
|---|---|---|---|
| **T0 底线（5）** | 0 | 0 | **5** |
| T1 行为（16） | 2 | 9 | 5 |
| T2 参数（2） | 0 | 1 | 1 |

**T0 底线 5 个维度 100% 互斥，零例外。**

⇒ **机制解释**：底线条款必须按各家的法律立场、产品定位、地缘合规单独定制，写法必然不同——**共享等位比随机还少**。行为条款是套话，所以趋同或中性。

⇒ ★ **这重新解释了上一轮的一个谜团**：「5 条 Tier 0 底线基因没有一家写全」**不是缺陷，是定制化的必然结果**。底线维度上的「一致性」本来就不该追求。

## 4. 对框架草案的三处修订

| 上一轮框架 | 修订后 | 依据 |
|---|---|---|
| 共识序用「证据门控 + 成对先后归一 + 相邻交换修复」 | **共识序 = 位点支持度降序**；另立**区分序 = 稀有度升序** | §2.1 |
| L3 建家族树（PhyloLM 式 NJ） | **L3 只在存在性层做**；等位层禁止聚类，改为「差异位点表」；树降级为辅助视图 | §2.3 · §3.4 |
| 粗序列三带编码 `█/▄/·` | **位点存在性（共识骨架）+ 等位取值（个体特征）分开编码**；等位带「趋同比值」标签 | §2.2 · §3.3 |

**新增可机检判据**：
1. 每维度必报「等位趋同比值」；判为互斥型的维度**禁止跨厂商等位聚类**，其等位差异只作并列展示。
2. 每维度必报「私有等位占比」；> 70% 的维度说明该维度的等位不可对齐，只能做存在性比较。
3. 存在性层的家族聚类必须附 null 树对照（保住每家广度 + 每位点全局频次，只打散共现）。
4. 任何「相似度」类指标必须写明**是存在性相似还是等位相似**，两者不可混用。

## 5. 本轮修掉的自身问题（都是量具，不是数据）

| # | 问题 | 后果 | 修法 |
|---|---|---|---|
| 1 | null 对照洗牌**厂商标签**后取全部配对 | 配对距离的多重集根本没变 ⇒ null 恒等于实测 | null 必须打散**共现关系**（保边际重抽） |
| 2 | null 函数**闭包引用真实数据** | 同上，null 退化成实测 | 相似度函数显式接收数据结构 |
| 3 | 抽样 null 从全局池重抽，高频等位重复入池 | null 被高估 ⇒ 误判成「厂商刻意互斥」 | 改用**解析期望**（§3.3） |
| 4 | 自写 flanking 规则时把 `_` 的限制错套到 `**` | 漏报 246 处 | 以 `pandoc -f gfm` 为 oracle |

★ **共性教训：null 对照最容易错在「洗错了东西」**。三个 bug 都是同一个形状——null 看起来在跑，但没打到要打散的那个维度。

## 6. 诚实边界

- **未在本地跑通任何一个候选件**；所有「能不能用」基于实现形态与作者自述限制。
- SPDeconstruction 语料**不含** ANTHROPIC 的 `CLAUDE-OPUS-5.5.md` 等 10 份、OPENAI 的 10 份 ⇒ 跨厂商对比受此限制。
- 「等位趋同比值」只在 **15 家 × 23 维** 上算过；26 家全体的比值待补（缺 SPDeconstruction 对应的 11 家）。
- 条款级数据来自 **gemini-flash-3.5** 一次生成，**非黄金标准**。
- 「互斥型 ⇒ 定制化」是**机制解释**，不是因果证明；本轮只证明了「共享度低于随机」。
- 行为层（强制度条款是否真被执行）**仍未验证**。
