GRL 基因规约语

Gene-Rule Language —— 规则是一等数据，散文是它的编译产物。已在 5526 条真实条款（38 文件 / 15 厂商）上跑通反编译到编译的闭环，18 条机检判据全部通过，其中一条是刻意注入违规的自证靶子。

VERDICT: PASS

§1定位：它填的是哪块空白

上一轮调研确认了三处行业空白：强度 / 模态字段、作用域字段、条款 ID 与评测分数的关联键。GRL 就是这三处的填补物 —— 它的必填字段恰好就是那三个空白。

它是什么
  • 规则的一等数据表示
  • 跨厂商可比较的坐标系
  • 提示词基因编码的等位层实现
  • 散文由编译器生成
它不是什么
  • 不是自然语言的替代品
  • 不是行为约束引擎
  • 不是通用策略语言
  • 不是行业标准
它填的空白
  • 强度字段（有序等级，非布尔）
  • 作用域字段（原文 + 归一键）
  • 条款 ID 与评测分数的关联键
  • 位点级 diff

§2语法速览

刻意做成 JSONC：LLM 输出 JSON 的可靠性远高于任何自定义语法，而机检成本最低。散文里的表格、引用、优先级声明全部下沉成数据字段。

{
  "id": "R-ANTH-SAF-0007",
  "locus": "D01",
  "tier": 0,
  "class": "regulative",
  "modality": "must",
  "negation": "no",
  "scope": { "key": "core search behaviors", "raw": "Core Search Behaviors" },
  "addressee": "you",
  "verb": "use",
  "object": { "key": "queries relevant them", "raw": "them for relevant queries" },
  "condition": "when internal tools are available",
  "truncated": true,
  "eval": ["safety.refusal_rate"],
  "provenance": { "vendor": "ANTHROPIC", "file": "Claude-4.1.json" }
}
四个字段的实测依据
  • modality 的 6 个取值 = 语料 10 种原始表述的归并结果
  • negation 是三态字符串而非布尔 —— 缺失与相同必须可区分
  • scope 同时存归一键与原文 —— 原始名有 295 个变体
  • eval 故意留空 —— 机制已定义，真实分数还没挂

四种引用形态：这就是「代指特定规则」

#D01
位点引用 —— 一个维度下的全部规则
存在性层；命中量有上限检查，防止过滤失效
#D01~must
等位引用 —— 该维度下所有 must 模态的规则
等位层；不指名文件，但精确到语义等价类
@R-ANTH-SAF-0007
精确引用 —— 指定的那一条
个体层；跨厂商可指向同一条规则
A ⊇ B
断言引用 —— 集合之间的可判定关系
验证层；⊇ / ⊥ / ≡ 三种，全部可机检

§6编译器契约：风格表数据驱动 + 强度守恒

渲染策略（各家文风）是数据不是代码。编译器必须自证两条，缺一不可：极性守恒（must 不许编译成 never / must not）与强度保档（must 不许降级成 may）。只查极性会漏掉降级，只查档位会漏掉极性反转 —— 两种漏法在实测中都真实发生过。

xai_policy     open=<policy>  close=</policy>  must→MUST   frame={body}.
openai_plain   open=           close=            must→must   frame={body}.
anthropic_effect open=         close=            must→always frame={body}, because it directly affects the user.

§7跑起来才暴露的 7 个真缺陷

设计本身不产生证据。以下全部是在跑真实语料时暴露的，其中第 7 条是判据自己有洞。

#缺陷症状修法类别
1编译器槽位粘连输出 search resultsalways槽位用列表拼接 + 空槽守卫实现
2风格表极性反转must 被渲染成 never，语义相反风格措辞纳入受控强度词表实现
3三态字符串被当布尔if rule.negation 把 'no' 当真显式 == 'yes'实现
4否定过计章节名 or not search 被当否定（124 条）否定扫描排除作用域，只扫正文实现
5上游数据污染C 槽混装 section + 语义截断剥离 + 显式 truncated 标记数据
6极性探测器复合模态must not 拆 token 后首个是 must（190 条误判）极性从编译器写入的模态槽判定实现
7判据自己有洞C3 空 token 集误判；C8a 命中 5526 条=全集仍判 PASS；C11 恒真空集守卫 + 命中量加上限 + 自证探针★ 判据

第 7 条最值得记住：PASS 不等于判据正确。C8a 抓到了 5526 条（全集）却仍然 PASS，因为判据只写了「大于等于 1」。给命中量加下限是弱判据，给它加上限才是强判据 —— 上限能抓住过滤条件失效导致的全集命中。

§9边界：明确没做什么

数据边界
  • 语料只覆盖 15 厂商，另 11 家无产物
  • 条款数据是 gemini-flash-3.5 一次生成，非黄金标准
  • 上游缺陷已量化并标记，但消不掉
  • 位点自动归属唯一率仅 54.6%
验证边界
  • eval 字段是空的：机制已定义，没挂真实评测分数
  • 行为层一次都没验：规则是否真被执行未测
  • 正编译不还原原文：它生成新散文，不是复刻
  • 位点级 diff 只做了 6 组厂商对，样本偏小

这是我的设计，不是行业标准：命名、ID 格式、引用形态都是本轮定的，没有与任何外部规范对齐过。
