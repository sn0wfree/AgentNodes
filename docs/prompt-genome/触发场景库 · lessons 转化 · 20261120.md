## 0. 一句话

**敲除实验的弹药已经造好了**——20 条真实教训就是 20 个「规则确实起过作用」的历史现场；把每个事故现场改写成触发场景，敲除对照就有了天然的场景库，不需要凭空设计。

**关键发现**：R-019 教训（「门禁看 0 违规不够，要注入已知违规看会不会红」）**就是 C10 量具校准制度的仓内实践先例**——量具校准不是新发明，是把已有纪律推广到新观测通道。

## 1. 转化规则

每条教训映射为场景库一条目：`{教训, 升入规则, 触发场景草案, 应力类型, 预期表型}`。

**应力类型**（依科学维度补充 S2 电容范式——规则平时被缓冲，压应力下才显效）：
- **常规**：正常工作流即可触发（验证规则的基本表达）
- **边界值**：空值/零值/极值输入
- **对抗**：注入违规/绕过尝试（规则的防御面）
- **故障注入**：kill/崩溃/资源耗尽
- **并发**：多 worker/多写者
- **平台**：跨平台差异
- **累积**：多批次变更后的复合状态
- **环境**：引擎/入口/依赖切换

## 3. 三条直接结论

1. **M3 的场景库骨架已存在**——20 条教训 → 20+ 场景草案，压应力分布合理（对抗 2 / 边界 1 / 故障 1 / 并发 1 / 平台 2 / 累积 2 / 环境 2 / 常规 8+）。A1 先导敲除选场景时直接从对抗型 + 边界值型取（电容实验：压应力下最可能显效）。
2. **C10 量具校准不是新发明**——R-019 教训的「注入法」就是校准协议的仓内实践（8 道门禁逐一注入验证会红）。推广动作 = 把同一纪律应用到新观测通道（rule_check regex/judge），并写进校准样本集制度。
3. **教训→规则→场景→敲除→（新教训）构成完整闭环的实物证据**——R-002 来源是 L2（2026-11-09），R-009 来源是 L2 预算事故，R-019 来源是 L2 门禁事故：**拉马克通道的真实运转记录已经在台账里**，规则基因组只是给它装上可观测仪表。

## 4. 诚实边界
