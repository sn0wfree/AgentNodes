# 提示词「基因序列」框架 · 业界先例调研

> **问题**：我们要设计一套「**自动提取语义维度 → 生成基因序列 → 跨来源对齐**」的逻辑框架。业界是否已有类似设计？
> **快照**：2026-11-17。本轮为**调研轮**，产出「先例地图 + 空白地图 + 框架草案」；框架草案是**本报告提出的设计**，不是既有事实。
> **可视化页**：`prompt-genome-lit/index.html`（35 个 P1–P5 先例的覆盖矩阵 + 11 个周边先例 + 10 条设计决策 + 24 抄件 / 13 自研件 / 14 条自检）。

## 0. 一句话结论

**没有直接先例。** 但不是一个空白市场——它由四个成熟零件拼成，而**没有人把这四个零件串成我们需要的那个闭环**。

| 我们的子问题 | 业界最接近 | 缺的那一环 |
|---|---|---|
| ① 把 prompt 切成带类型的条款 | **SystemPromptDeconstruction**（同一份 CL4R1T4S 语料，已拆好）、LLMON span tagger、PromptLint Parser | 类型集全是**人工预定义**的 |
| ② **自动发现**维度集（位点表） | MDPI 2026 的两段式 LLM 无监督聚类 | 没人用在 prompt 语料上；PromptPrism **明说自己是 top-down 手工的**，把自动标注列为 future work；DelvePO **自陈「dynamic component discovery 仍是空白」** |
| ③ 编成可对齐的**离散位点序列** | **已有 5 个明确先例**：DelvePO（**明写 Loci / Alleles**）、PromptGenome / arXiv 2611.01135（组件型 genome + **locus 级变异器**）、SEPO（typed units）、CFG-genotype、phenome | 这些都只服务**单条 prompt 的优化**；**跨 prompt 的逐位点对齐、共有位点比例、共识序、家族聚类全无** |
| ④ 跨来源对齐 + 家族聚类 | **PhyloLM**（prompt 当 gene、输出 token 当 allele、算等位比例相似度 → **NJ 树**）、ConGrs（Needleman-Wunsch 词级对齐）、SystemPromptDeconstruction（SBERT+UMAP+层次聚类+dendrogram） | PhyloLM **把树长在模型上，不是 prompt 上**——**方法论最近、对象错位一层**；其余两个一个比对的是同一模型的多次**回答**，一个聚类走**连续向量** |

**关键判别 ①**：进化式提示词优化文献（EvoPrompt / GPS / Promptbreeder / PhaseEvo…）里到处写「prompt as genome」，但那里的 genome 是**搜索表示**（种群 / 突变 / 交叉 / 适应度），**不是**「让不同 prompt 逐位点可比」的比较编码。§3.6 专门拆。

**关键判别 ②**：真正把 prompt 做成「**离散基因型**」的先例确实存在且不止一个（DelvePO / PromptGenome / SEPO / CFG-genotype / phenome），**但它们全部把「位点集从哪来」当作人工前提**；而把「位点集自动发现」做出来的那类方法（MDPI 的两段式聚类）又**只产出标签 + 代表句**，不是可直接当 schema 的位点表。**两半之间没有人搭桥——这正是我们的位置。**

## 1. 判据：什么算「类似的设计」

把「自动提取维度并生成基因序列」拆成五个可独立判定的子问题。**每一项都必须单独回答「有 / 没有 / 只有邻近技术」**，否则「有类似设计」这句话没有信息量。

| 编号 | 子问题 | 判定标准（满足才算） |
|---|---|---|
| **P1** | 条款级切分 | 能把长 system prompt 切成**有类型标签的原子条款**（不是按 markdown 标题切） |
| **P2** | 位点集自动发现 | 维度集本身是**从语料里归纳出来的**，不是人先写死的 |
| **P3** | 离散编码 | 每个 prompt 映射成**固定槽位上的离散取值**，不同 prompt **可逐槽位比较** |
| **P4** | 跨源对齐 | 能算「共有位点比例 / 逐位点差异」，且能产出**共识序**（consensus order） |
| **P5** | 家族聚类 | 能在基因序列上做**家族聚类**（存在集距离 + 树），而不是只有 embedding 聚类 |

再细分两轴（**这轴是我们上一轮的关键发现，业界几乎没人分**）：

- **覆盖广度**：多少家写到该维度
- **约束强度**：写到的那家里，有多少把它写成**条款级强制**而不是散文

phenome / prompt-genome / SysPrompt-Forge 三家都**没有**这个区分。

## 3. 逐个拆解

### 3.0 先把话说清楚：**「把 prompt 做成离散基因型」这件事，业界已经有人做了**

这是本轮最重要的更正——**我在调研中途的初稿里判断「P3 离散编码没有先例」，这是错的**。把 arXiv 全库翻完之后，至少有 **5 个明确先例**用了 loci/alleles 这套词汇，而且其中一个（PromptGenome）连「**locus 级变异器 + 部署前的晋级门**」都做出来了，几乎就是我们框架的演化层。

| 项目 | 「基因型」的形态 | 位点从哪来 | 跨 prompt 对齐 |
|---|---|---|---|
| **DelvePO** | HTML tag 组件，**组件＝loci、取值＝alleles** | **人工预定义**（它自陈：dynamic component discovery 仍是空白） | 无 |
| **PromptGenome**（2611.01135） | 组件型 genome（role / constraints / reasoning directives / few-shot blocks / output directives / verification hooks） | **人工预定义** | 无 |
| **SEPO**（2608.28067） | 两层 schema + **稳定 typed units** | **人工预定义** | 无 |
| **Diverse Prompts**（2504.14367） | **CFG 推导树当 genotype** | 文法规则**人工写**，但**每条 prompt 的基因型是自动推导出来的** | 无（但 MAP-Elites 档案按 trait 分箱 ≈「描述子直方图」） |
| **phenome** | 64 loci × 251 等位 × 4 强度 | **人工手写 registry** | 无 |

**⇒ P3 的真相是**：
- 「**一条 prompt → 一串有名字的离散槽位**」：**已有先例，且至少有 5 个**；
- 「**位点集本身从语料里长出来**」：**仍是空白**（DelvePO 自己把这条列为空白）；
- 「**不同 prompt 的槽位可一一对齐、缺失可记 gap、等位可 canonicalize 成符号**」：**仍是空白**。

**这三个「已有/空白」的切分，就是我们的项目边界。**

再补一个**方法论上最近、对象错位一层**的：**PhyloLM**（arXiv 2404.04671, ICLR 2025）。
它把 prompt 当作 **gene（探针）**、把**模型的输出 token 当作 allele**，用「两模型在同一 probe 下输出 token 的匹配比例」当距离，再建 **Neighbor-Joining 树**——**用的正是「基因 / 等位 / 相似度 / 系统发育」这套词汇**，并用系统发育相似度预测基准分（r≈0.68）。
★ **它的树长在「模型」上，不是长在「prompt 的组成部分」上。** 我们要做的正是**把同一套方法横移一层**：从「模型 × 探针」矩阵换成「厂商 × 位点」矩阵，距离从「输出 token 匹配比例」换成「等位符号共享比例」。
★ 它的建树管线（distance matrix → NJ dendrogram → 支撑度 → 性能预测）是**可以直接复用的一整套代码**，只要换掉距离定义。
★ 它的 repo 只有 **18★**，说明这条路**方法上成熟、生态上冷门**——正是「无人做但可做」的典型位置。

### 3.1 phenome —— **名字最像、形态最像，但目标不同**

这是唯一一个**真的把 prompt 换成「基因串」的**公开项目，也是本轮最重要的发现。

**已核实的机制**（读到 `phenome/prompt.py` 源码与作者原文）：

- **位点表**：作者**手写**了 64 个 trait loci（verbosity / formality / warmth / humor / structure / markdown / banned-openers / profanity / domain skill / safety posture …），251 个等位，每个等位 4 档强度 ⇒ 共 **1004 段手写 phenotype 片段**。其中 21 个 locus 是「always-on 通用助手」，其余按域激活（coding / medical / legal / therapy / RP / NSFW）。
- **编码**：`alpha6` 为默认训练形态，**每 locus 6 字符**（`LL` = 两位 base-26 locus 序号 + `a` 等位 + `a` 强度 + `b` 等位 + `b` 强度）；另有 `named`（可读）、`positional`（去名保 tag）、`hex6`（数值消融）三个变体。**只有 alpha6 实现了逆解码**，其余是 emit-only（源码里明写）。
- **体量**：完整基因组 **120 字符**，在 Qwen BPE 下 **≈110 token**；作者对比「一份好 AI 伴侣的 system prompt 是 3–5k token」。
- **训练**：75k 条合成数据，LoRA 挂在 **Qwen3.5-0.8B-Abliterated**（rank 16 / alpha 32 / 1 epoch），单卡 H100 5–6 小时。
- **效果**：LoRA 让输出「在 68%（34/50 二元方向测试）上可见地朝基因组指定方向偏移」。最强信号轴：identity-opener 抑制、markdown/结构合规、format-shape 控制、register 倾斜。

**和我们要做的事的三点根本差异**：

1. **目的相反**：phenome 要**替换** prompt（压缩，用 110 token 顶掉 3–5k token）；我们要**描述** prompt（审计、对齐、比较）。它是被测物的替身，我们是被测物的表示。
2. **位点是人写的**：64 loci 来自作者一个人的领域直觉，不是从语料里发现的 ⇒ **P2 缺失**。
3. **没有跨源对齐**：它的等位表只服务于「同一 registry 下的解码」；**没有任何两个 prompt 之间的逐位点比较、共识序、家族聚类** ⇒ **P4 / P5 缺失**。

**但它给了三样可直接抄的东西**：
- **编码格式的层次**（稠密机器形态 / 可读命名形态 / 消融形态三件套，且显式声明「只有一种需要逆解码」）——这条设计原则我们该照抄：*位点编码要同时有「机器用」和「人读」两种形态，且明确唯一真源*。
- **强度分级进编码**（每等位 4 档）——和我们上一轮「区分『写到了』与『写成强制条款』」的方向一致。
- **它自己的坦白**：68% 只说明「方向被推动」，**不说明约束被遵守**。这与我们上一轮「强制度只是代理指标」的边界完全同构，可以直接引用作为外部佐证。

### 3.2 Prompt Genome —— **单条 prompt 的「基因化」做得最完整**

**已核实**（README 全文）：粘贴一条 prompt → 切成 typed, color-coded genes（`role` / `persona` / `context` / `task` / `constraint` / `format` / `example`）；显式标签（`Constraints:`、`## Format`）被优先采纳，自由散文**逐句**分类，**每个 gene 会显示「为什么被判成这一类」**（"forbids something" / "imperative verb"）。

配套能力：
- **Lint**：0–100 分 + 带严重级的发现（无 task gene、任务冲突、含糊措辞 "various things, etc."、主观质量词 "engaging"、"high-quality"、简/深冲突、只有负向约束、重复 gene、缺 format/example、超长 gene）。
- **Mutate**：每个 gene 类型三个**确定性**重写（如 constraint → Harden it / Soften it / **Make it checkable**），带一行理由 + 内联预览。同一 gene 进 → 同样三个出。
- **Diff**：词级 LCS，对比「粘贴原文」vs「编辑后的基因组」。
- **Library / Export**：localStorage 按 tag 检索复用；导出 Markdown / JSON；分享链接把整个基因组 base64url 塞进 URL hash。
- **工程**：87 个测试，core 覆盖率 ~99%，零运行时依赖，vanilla TS + Vite。

**它离我们还差什么**：
- **只处理一条 prompt**（没有「一批 prompt」的横向对齐概念）。
- **gene 类型固定 7 类，手写**。
- 它自己在 README 里交代了限制：**分类器只认它出厂带的那套 cue 词**，遇到怪句就**回退到 `context` 并标「no strong signal」**，逃生口是人工一键改类。
  ⇒ **这条限制对我们是警告**：规则式位点取值器必须有「未识别」这个**一等状态**，不能把兜底当答案（这与我们上一轮「缺失即失败、禁止默认值兜底」的结论同向）。

### 3.3 PromptPrism —— **最学术的分类学，也是最明确暴露空白的地方**

**已核实**（arXiv 2505.12592，Amazon AWS）：三层语言学分类
- **结构层**：System / User / Assistant / Tools 四种角色 + 单轮/多轮会话模式
- **语义层**：Instructions / Contextual Information / Output Constraints / Request-Question（每类还有子类）
- **句法层**：Delimiters / Directive Markers / Special Tokens

三个应用：① **taxonomy-guided 精修**（在 Super Natural Instruction 的 apigen-80k / smol-magpie-ultra 上，精修后的表现优于 baseline 并追平 CoT）；② **多维数据集画像**（抽取并聚合结构/语义/句法特征）；③ **受控敏感性分析**（语义重排、分隔符改写、组件消融）。

**★ 最有价值的一句话是它的「局限」段**（这一点直接决定了我们项目的定位）：

> - **Top-Down Design**: the taxonomy was designed based on **expert knowledge rather than empirically derived from large-scale prompt analysis**
> - **Manual Annotation**: some aspects of the taxonomy application require manual effort
> - Future Work: **Automated Annotation** — Developing machine learning approaches to automatically apply the taxonomy to large prompt collections

⇒ **离我们最近的学术工作，自己声明「维度集是手工的、自动归纳没做」。** 这是本轮最干净的一条「空白」证据。

另外它的**数据集画像**是「聚合分布」（这批数据集里多少比例有 format 约束），**不是**「逐 prompt 的可对齐序列」⇒ **P4 仍然缺失**。

### 3.4 SystemPromptDeconstruction —— **在我们的同一份语料上做过一遍，是最有价值的对照物**

我把它 clone 到本地（`/workspace/research/lit/spd`）逐行读了源码。它的流水线是：

**Step 1 · 原子拆分**（`llm_processing_pipeline/pipeline_prompts/parsing_system_prompt.txt`，17.9 KB，我读了全文）
把 system prompt 拆成**原子陈述**，每条只含一个 Attribute / Deontic / Aim / Object，两个字段：
- `statement` —— **逐字原文**（拆句后取到的那一段）
- `with-context` —— **自足改写**（补上所属标题的上下文，如 "Under Behavioral Guidelines regarding tone, you are always concise."）

拆分规则写得很硬：按连词拆、按分号拆、复合谓语拆、复杂分句拆；**保留标题锚点**；**忽略示例**，除非示例里含别处没有的新规则。

**Step 2 · IG 分类**（`classification_system_prompt.txt`，11 KB，我读了全文）
三步 litmus test：`non-statement`（动态注入 / 时间戳 / 环境变量）→ `regulative`（施加规则、含命令或情态动词）→ `constitutive`（定义身份/本质，无命令无条件）。然后抽字段：
- constitutive：`E` 实体 / `F` 功能动词 / `P` 属性
- regulative：`A` 受话人 / `D` **deontic（只认显式出现的 must/can/should/may）** / `I` 目的动词 / `B` 宾语 / `C` 条件

**Step 3 · 指标**（`analysis/indicators.py`）：`S` 字符数、`NCtW` 非代码占比、`NStNC` 非陈述占比、`CStA` constitutive 占比、`StRS` 策略占比、`CtRS` 命令占比（must/should）、`PRtRS` 许可占比（may/can）、`PHtRS` 禁止占比（must not/may not）。

**Step 4 · 表征**（`analysis/embeddings.py`）：Sentence-BERT → UMAP/PCA/tSNE → KMeans/Agglomerative(ward)/Spectral/DBSCAN + scipy `linkage`/`dendrogram`（注释里直接写 "family tree"）。

**Step 5 · 产物**：他们把处理结果也放进了仓库——`CL4R1T4S-no-code-processed-gemini-flash-3_5/classification/` 下 **38 个 JSON / 15 个厂商目录**，模型是 gemini-flash-3_5。样例（`ANTHROPIC/Claude-4.1.json`，**643 条陈述**）：

```json
{"anchor":"You are Claude","full_statement":"Under Opening Context, you are Claude.",
 "class":"constitutive","constitutive_components":{"E":"you","F":"are","P":"Claude"},
 "regulative_components":null}
```

**它与我们方案的差异（一句话）**：
它的分类是**人工预定义的**（3 类 + 7 个 IG 字段），聚类走**连续 embedding** ⇒ **P2 缺、P3 缺、P4 缺**。
但它的**原子拆分提示词**和**IG 分类提示词**是**可直接当我们的抽取基线**，而且它已经把 **CL4R1T4S 拆好了**（38 个 JSON 在库里）——⇒ **我们可以先拿它的产物跑通我们的编码层，再回头做自动发现**，这是最短路径。

⚠️ 提醒：它用 gemini-flash-3_5 跑出来的 643 条陈述，**是「一个模型的一次输出」**，不是人工标注的黄金标准。它的 `validation_app/`（Streamlit）就是用来人工校验这些标注的——这恰好说明**这类抽取必须带人工校验环节**，不能默认信。

### 3.5 LLMON span tagger —— **现成的 token 级条款切分器**

IBM 的 149M ModernBERT token 分类器，7 个 BIO tag → 3 类：**instruction / constraint / data**（annotation 原为 9 类，标注时塌缩成 3 类）。模型卡原文给的数：

| 后端 | Recall | Precision | F1 | 句中边界召回 | 断句处召回 |
|---|---|---|---|---|---|
| 规则基线 | 68.2 | 69.3 | 68.8 | 18.3% | 81.5% |
| llmon-span-tagger | 78.3 | 77.0 | **77.7** | **61.1%** | 92.0% |

**它自己列的坑（全部要抄进我们的边界声明）**：只支持英文；2048 token 后**静默截断**不报错；**过切分 +24%**（665 预测 vs 535 真值）；confidence **未校准**；**训练种子单独能移动 holdout 分数 8.8 个点**；holdout 被复用于调阈值与选 checkpoint ⇒ 分数偏乐观；134 条 holdout **不公开**；训练语料来自 IFEval/MMLU/InfoBench/ComplexBench，**system prompt / agent prompt 严重欠采样**；**不得当安全控制用**（误判会把攻击者的文本提升为指令）。

⇒ 对我们：**它可以当「规则式切分的对照基线」直接跑**（尤其因为我们的语料是英文），但**不能当位点取值器**（3 类太平，无法区分 Constraint / Output Format / Role / Example）。

### 3.6 进化式提示词优化 —— **「prompt as genome」在这条线上的含义与我们完全不同**

这是本轮最容易读混的地方，必须拆清楚。

EoT 这条线里 genome 有**四种编码**（Emergent Mind 条目归纳）：
1. **有序条款列表**（句子 / XML 块为单位）
2. **token 序列**
3. **二值掩码**（对 few-shot demo token 集合做剪枝，如 PromptQuine）
4. **图增强**（与知识图谱/因果图一起构成 genome，如 EGO-Prompt）

代表方法与数（读到的）：PhaseEvo（BBH +46%，约 4k 次调用）、EvoPrompt（Guo et al. 2023，连接式进化）、GPS（Hanwei Xu，Genetic Prompt Search）、PromptQuine（掩码自复制，低数据下 +7.9%）、DEEVO（辩论 + Elo，无 ground truth 也能优化）、GAAPO、ReflectivePrompt（BBH +28%）、MOPrompt / EmoPrompts（NSGA-II / MOEA，多目标 Pareto 前沿）、C-Evolve（**组共识投票**，HotpotQA F1 +4.95）、EGO-Prompt（+12.6% F1）、EPiC（代码，HumanEval pass@1 51.7%，成本 6–8× 更低）。

**★ 判定**：在这条线里，genome 是**搜索表示**——它的目的是让变异/交叉算子能在离散空间里动。它优化的是「**一个** prompt 好不好」，从不回答「**A 家的 prompt 和 B 家的 prompt 在第 7 个位点上是不是同一个等位**」。

⇒ **对我们的意义**：
- ✅ **可复用**：变异算子（Harden / Soften / Make-it-checkable 这类确定性变换）、交叉（把两个 prompt 的条款按位点重组）、适应度函数（我们没有 ground truth，但可以用「家族一致性 / 位点覆盖 / 强制度」做代理适应度）。
- ❌ **不可复用**：它不提供位点 schema，也不提供对齐。
- ★ **一个可以顺手拿的**：SPRIG 那类「**进化系统提示词本身**」的工作，说明「用我们编出来的基因序列当种子去优化一个真实 system prompt」是一条现实存在的下游需求。

### 3.7 ConGrs —— **文本多重序列比对的现成算法原型**

**已核实**：把 **Needleman-Wunsch 改造到词级**，对同一模型高温采样 m 次回答做多重比对，构建 DAG：
- **共识节点**：所有回答共有的 span
- **分歧节点**：分叉路径，用轻量二级 LM 做成对语义聚类
- 边权 = 支持该路径的回答比例

**结果**：传记/长文事实精确率 +31–56%（FActScore）；二级 LM token 比 UAD 少 **82%**；False Presuppositions 上的无根据回答 −56%、幻觉率 −58%；MATH 上引导自验证比自洽性投票 +2–6 个点。

**★ 它的关键洞察直接可以搬**：RLHF 会在输出里造出**顺序固定的「anchor span」**（同一段话在多次采样里按同样顺序复现）⇒ 纯词法比对就能把结构骨架抠出来，不用烧 LLM token。
**★ 它自己的边界**：开放式创作任务里共识节点极少，图几乎退化（所以只用于事实/推理任务）；人工审计发现它偶尔**丢掉有效事实**（100 条里 5 条）。

**★ 对我们**：这就是 P4 的算法原型（只是它比对的是**同一模型的多次回答**，不是**不同来源的 prompt**）。把它移植到「条款序列」上，需要把比对单位从「词」换成「条款/位点取值」，并把 gap 语义从「插入删除」换成「**该家在此位点缺位 / 取了私有等位**」。

### 3.8 LLM 无监督语义维度发现 —— **P2 的算法原型**

MDPI *Mathematics* 2026 那篇（非 prompt 域，但是方法论最直接可搬的一篇）：

**两段式**：
1. **分段聚类**：把 N 条短句分批丢给 LLM，要求「**不用任何预定义实体类型**，按语义相似度自由聚类，组数由语义自然决定」，每批产出带自然语言标签的组 → 12,163 条中药记录 / 64,107 句 → **458 个原始标签**
2. **合并成概念**：把 458 个标签再喂给 LLM，合并成高层概念 → **22 个语义类别**

**评测**：Qwen3-Embedding-8B 算概念内聚（19 个概念 ≥60%，11 个 ≥70%）；10 位领域专家打分 **4.64/5**；飞机装配手册上复现出 12 个概念（内聚 46.6% vs 随机基线 10–25%）；与 k-means（3.42）、LDA（2.11）对比，本方法 **4.42**，差距主要在可解释性。

**★ 它自己承认的三条限制，正好是我们设计时必须补的**：
- **层次是扁的**（只给类别，不给 subClassOf 等关系）
- **对罕见概念敏感**（低频句容易掉进 "Other" 兜底类）
- **兜底类内聚只有 36.91%**，远低于其它任何概念 ⇒ 兜底类本身不可用
- **★ 最要命的一条：确定性**——温度 0.3 下「输出并不严格确定」，重复跑 **簇数最多差 15%**；最终 22 概念在重复跑之间「保持稳定」是作者的观察结论，不是保证。

⇒ **我们的维度发现必须自带一个「稳定性闸」**：同一语料跑 N 次，位点集的 Jaccard 相似度低于阈值就判定发现失败（而不是拿一个不稳定的结果当 schema）。**这条是从它的局限里学来的，不是我们拍脑袋加的。**

### 3.9 跨模型表征对齐（SAE / transcoder / steering）—— **连续路线，可以借判据，不能借形态**

Cross-Architecture Steering Transfer（arXiv 2608.05164）的一手数：
- 每个模型训一个 SAE（扩展 64×–128×），在 CCA 投影空间用 **MNN（互最近邻）** 配对特征，要求对齐分 ≥0.70
- 验证门：`Pearson r ≥ 0.60`（R² ≥ 0.36），并做 Benjamini–Hochberg FDR 校正
- **规模断层**：≥1.7B 参数时 47–49% 特征对过阈；<0.8B 时急剧劣化
- 功能迁移：跨模型 steering 向量胜率 **71.0%** vs 同模型原生 **68.0%**（差异方向性但 p=0.14，作者明说**统计不显著**）；无监督通用向量在 5 个模型中 4 个达 67.3%
- **算力**：整条流水线 ≈ **52 A100·小时**
- 作者的**诚实失败记录**（附录 O）：第一版用 Hungarian 配对得到 1,823 对、过阈率 68.4%，**是虚高**（预选 top-K 抬高了 Cohen's d，且无向池化掩盖了规模断层）→ 换成 MNN 后降到 **45.5%**，作者明说「**45.5% 不是回归，是更诚实的估计**」。

Crosscoders 一侧的关键工程细节：**用朴素 L1 稀疏会造出「完全收缩」和「latent 解耦」两种伪影** ⇒ 必须用 BatchTopK + latent scaling。

⇒ **对我们的意义**：
- ❌ 不能直接当「基因序列」：连续向量不可审计、不可逐位点阅读、且**闭源前沿模型根本没有激活可取**（该论文自己把 GPT-4/Claude/Gemini 列为 out of scope）。
- ✅ **可借三样判据**：① **MNN 互最近邻**做对齐（比 Hungarian 全局 1:1 更诚实，理由见上）；② **多重指标门**（相关性 + 置换/伪影校正）；③ **量具自曝的诚实记录**（作者主动写「45.5% 是更诚实的估计」——这正是我们该有的写法）。
- ★ **一条直接的警告**：SAE 的对齐在 <1.7B 就塌了。**任何「学出来的对齐」都有规模下限**；而我们做的是**文本层对齐**，下限在「词表与规则覆盖率」而非参数量——**但同样要显式量化，不能假设**。

### 3.10 其它两个「人工维度集」—— **当作外部交叉验证，不是当方案**

- **SysPrompt-Forge** 的 7 条设计轴（personality / tool-use philosophy / context strategy / memory approach / planning style / verbosity / proactiveness）+ 5 个行为原型（Builder / Architect / Generalist / Explorer / Tactician）。
- **Joshitadas/prompt_analyzer** 的 6 条原则（context / machine treatment / constraints / format / examples / role），每条给 Pass / Weak / Missing 判决。
- **system-prompt-archaeology**（LobeHub skill）：7 个结构层 + 6 个行为信号（pacing / depth / tone / initiative / validation / error_handling）+ 4 个行为原型。

**★ 三家独立（互不相识）的人工维度集，落在同一片区域**：身份/风格 → 工具与环境 → 输出格式 → 计划/自主 → 验证/诚实 → 约束/边界。这**独立佐证了我们上一轮的 D01–D23 不是拍脑袋**，也提示：**我们的维度集应该允许被外部人工维度集对齐/挑战，而不是封闭自洽**。


### 3.11 自动发现维度集 —— **P2 并不是「一片空白」，而是四条真实路线（但没有一条产出「一批 prompt 的共享位点表」）**

★ 这一节是对 §0 判断的重要补充：**我最初写「P2 是真空白」，读完第二路子任务的检索后必须修正**。

| 路线 | 代表 | 维度从哪来 | 关键数 | 为什么还不是我们要的 |
|---|---|---|---|---|
| **① 语料 → 多维 taxonomy** | **TaxoAdapt**（ACL 2025 Main, 2506.10737） | **维度名人工给**（task / methodology / dataset / evaluation / real-world domain），**维度内节点全自动** | 5 项质量指标，人工一致率 70–90% | 维度名仍要人写；域是论文不是 prompt |
| **② 失败案例 → 反向长维度** | **Auto-Prompt Ensemble**（2510.06538） | **全自动**：从 judge 与人类**判错的 case** 里长候选维度 | 88 候选→40 验证→**16 选用**；Reward Bench 87.2%→90.5%；**维度数 >4 开始涨点，14–16 达峰，跨域需 >10 维** | 依赖人类偏好标注当失败信号；域是 reward model |
| **③ 实例 → 隐式评测标准** | **EvalAgent**（COLM 2025, 2504.15219） | **全自动**：Query→Retrieve→Aggregate→Rank | 专门产出「**prompt 里没说但人会在意**」的隐式标准；自带 SS / II / AA / RR 四项评分；**Fleiss κ 仅 0.25–0.29** | 只验证写作类；依赖外部搜索 API |
| **④ 神经表征 → 离散主题** | **SAE-TM**（ICML 2026, 2511.16309） | **全自动**：SAE 目标 = 连续主题模型的 MAP 估计 ⇒ feature 即 thematic atom | **可合并成任意数量主题而无需重训** | 需要能取激活的前沿模型（闭源 API 做不到）；feature 非正交 |
| （补充）**多实例 → 质量维度** | 外科反馈质量维度（2605.25440） | **全自动**：多实例采样 + 合并 + 评分相似度聚类 | 6 维；AUROC 0.71–0.75；**维度间平均 \|Spearman\| 仅 0.26（≈正交）** | 单域；维度数上限仍要人工定 |

★ **可抄的三条判据**：
1. **维度数不能拍脑袋**：APE 给出了「维度数 vs 收益」的曲线形状（>4 起涨、14–16 达峰、跨域需 >10）⇒ 我们的 23 维度应当**报出这条曲线**，而不是只报「我们用了 23 个」。
2. **维度必须查正交性**：外科反馈那篇做了「维度间平均 \|Spearman\| 0.26」⇒ 我们的 D01–D23 也该有一张**维度相关性矩阵**，否则 23 个维度可能是同一个维度的 23 种说法。
3. **维度本身要有质量评分**：EvalAgent 的 **Specificity / Implicitness（与 prompt 的词重叠率）/ Actionability（编辑后满足率）/ Recall@k** 是现成的四把尺。

★ **仍然空白的格子（这才是我们的位置）**：以上四条路线，**没有一条的输入是「一批不同厂商的 system prompt」，输出是「一个跨厂商可复用的共享位点表」**。TaxoAdapt 的维度名是人给的；Prompts in the Wild 的本体字段也是人定义后自动标注；SAE-TM 需要激活。
⇒ **P2 的真相不是「没人做过」，而是「做过的都在别的域，且维度名/本体字段都还是人工前提」。**

### 3.12 取值器 —— **「标签即校验器」是比相似度更硬的一条路线**

我们要做的是「把一条自由文本条款判成某个位点的某个等位」。两条现成路线：

- **相似度路线**：**MICoL**（WWW 2022, 2202.05932）——**零样本多标签分类，只要 label 名称 + 描述**，不需要标注数据，**标签集可任意增删**。这是最干净的通用取值器。配套：ICXML（2311.09649）、Basile et al. 的 label description 选择/聚合（2204.09481）。
- **校验器路线（更硬）**：**IFEval**（2311.07911）的 25 类可验证指令 + **AutoIF**（2406.13542）的「instruction → verification function」——**每个位点配一个可执行校验器**，靠执行反馈而不是相似度取值。AutoIF 的自动验证器流水线：种子约束 → self-instruct 扩增 → LLM 写验证函数 + 单测 → 交叉验证 + NLI 反向翻译 → 执行反馈拒绝采样。

★ **对框架的直接影响**：我们的取值器应当是**双通道**——
- **软通道（MICoL 式）**：给「未识别 / 疑似」以连续分数，用于**兜底与排序**；
- **硬通道（IFEval 式）**：能写成可执行判定的位点，**必须有 verifier**，用「通过 / 不通过」而不是相似度定案。
★ 并且——**只有软通道能表达「未识别」这个一等状态**。这与我们上一轮定的「未识别不许兜底成默认等位」是同一条原则，两条路线在此接上了。

### 3.13 「强制条款 vs 散文」—— **法律域已经做出来了，可以整套搬**

★ 这是本轮对我们**最有直接价值**的一个发现，因为它正是我们上一轮最吃力的部分（覆盖广度 × 约束强度双口径）。

**ARCCS**（EMNLP 2026 System Demonstrations, 2610.01345）的做法：
法规 → **层级分段**（article / paragraph）→ **原子条款**，每条是一个 typed tuple：
`⟨法律功能 obligation / prohibition / right / condition, 规制主体, 适用范围, 强制条件集 M_i, 原文指针⟩`
并**显式过滤掉纯定义 / 纯描述 / 纯上下文条款**。

实测（原文数）：GDPR 100 条 requirement，LLM judge 一致率 90–96.67%、Fleiss κ = 0.69；EU 采购 1200 条 rule-level 决策，accuracy 98.5–98.8%、exact-match 87.0%。

配套件：**CUAD**（NeurIPS 2021 D&B, 2103.06268）——**41 类人工条款类型**（合同域）；Hierarchical RNN 的 obligation/prohibition 三标签（1805.03871）；Contract Verifier / ConPar 的句→条款抽取（F1 0.49–0.86）。

⇒ **对我们的意义**：我们上一轮用「按章节扫措辞」判强制度，是**没有先例的做法**；ARCCS 证明：「条款类型」+「强制条件集」+「原文指针」**是一个可机检的结构化表示**。我们的位点 schema 可以直接吸收这个形状：
`⟨位点语义类别, 主体/适用范围, 强制条件集 M_i, 原文 span 指针⟩`

### 3.14 基因位点 schema 的现成可抄件 —— **四个 0★ 小工具，比想象的更接近**

| 件 | 形态 | 可抄什么 | 坑 |
|---|---|---|---|
| **PromptSys**（HotFazz） | 12 类标签 + **7 种关系** + 冲突检测（DFS 找环 / 语义矛盾 / 重复 / 孤儿） | ★★ **条款类型枚举 + 位点间关系表**——我们的「位点依赖 / 冲突」可以整套借 | **0★、无 license、2025-11 才建**；`src/types/index.ts` 未读到，字段名以 README 为准 |

### 3.15 防泄漏 / 注入分类 / 版本 diff / 护栏格式 —— **四条周边线，含三条有价值的否定发现**

**（a）系统提示词泄漏检测**——商用方案成熟，但**没有一条是「prompt leak 专用规则」**：
- Cloudflare AI Gateway Guardrails：**类别码 = S1–S14（Llama Guard 3 危害类）+ P1（Prompt Injection，`@cf/meta/prompt-guard-2-86m`）**，动作 FLAG/BLOCK，错误码 2016/2017。★ **没有 "prompt leak" 这一类**——最接近的 S7 Privacy / S8 IP 是「内容危害类」，不是「模型是否吐出自己的 system prompt」。
- Cloudflare AI Security for Apps（WAF）：`cf.llm.prompt.injection_score`（1–99），文档明确覆盖 "ignore instructions or **reveal its system prompt**"——**泄漏只是注入分的一部分**。
- `guardrails-ai/detect_system_prompt_leakage`（0★，算法未读）、`meta-llama/Prompt-Guard-86M`、`NVIDIA/garak`（10,062★）。
- ★ **`protectai/llm-guard` 已被 GitHub 标记 `archived: true`**（3,216★，last push 2026-07-08）；**Lakera Guard 2025-09-16 宣布被 Check Point 收购、10-22 交割，改名 Check Point AI Guardrails**（API 仍是 `api.lakera.ai/v2/guard`）⇒ **引用这些工具前必须先确认它还活着**。

**（b）注入分类法**——三条一手：
- **Greshake et al.**（arXiv 2302.12173，*Not what you've signed up for*）：**indirect prompt injection** 的原始论文 + data theft / worming / information ecosystem contamination 三类影响。
- **OWASP LLM01:2025**：**Direct / Indirect** 两型，各自可 intentional / unintentional；**jailbreaking 是子类**。
- **Instruction Hierarchy**（Microsoft, arXiv **2404.13208**）：system > user > tool 的显式优先级。★ **2404.13213 不是这篇**（那是引力波论文），这是高频误引。

**（c）版本 diff**——★ **主流平台全部是文本 diff**：Langfuse（immutable version + label）、PromptLayer（registry + release label）、Agenta（variants/versions/environments，**连 diff 视图都没有**）。**语义 diff 只存在于 0–9★ 的个人仓库**（PromptDiff 9★ / llm-prompt-semantic-diff 6★ / prompt-git 4★）。
⇒ **对「基因位点 diff」的含义**：**「位点级 diff」（这一家多了哪些位点、某个位点的等位怎么变）目前无人做**，而它恰恰是位点 schema 一旦成立就**白送**的能力。

**（d）护栏 / policy 格式**——★ **三要素里只有一个有**：
- **NeMo Colang 2.0**：有**作用域**（`flow input rails $input_text` + `if / abort` 分支），**但强度 / 模态（必须 / 应当 / 禁止）完全缺失**——只能写在自然语言里让 LLM 自己理解，**没有可枚举字段**。
- **Guardrails Hub**：**没有统一的 policy 文件**（每个 validator 一个 Python 包）；NeMo 侧 `config.yml` 里 `parameters` / `metadata` 是**任意 dict，无 schema**。
⇒ **「模态 / 强度字段」是全行业空白**——这正面印证了我们上一轮把「强制度的结构化表达」列为必须自研项 #6 的判断，现在它有了跨 4 个独立生态的证据。

**（e）★ 一条被忽视的空白**：**条款 ID 与评测分数之间没有任何关联键**。Langfuse / Agenta / PromptLayer 的「版本 → 评测 → trace」链路与「条款 ID」**不存在公开的关联**。⇒ **这正是「基因位点」最缺的一环**：位点必须能挂到行为/评测分数上，否则位点只是一个描述，不是一个可晋级的基因。

## 4. 四个判定题，明确回答

**Q1：有没有把一批 prompt 编码成可对齐的离散位点序列？**
**前半有，后半没有。**
- **有（单条 prompt → 一串离散槽位）**：DelvePO（**明写 Loci / Alleles**）、PromptGenome（组件型 genome）、SEPO（typed units）、Diverse Prompts（CFG genotype）、phenome（64 loci × 251 等位）。
- **没有（跨 prompt 的对齐）**：这些都只为**单条 prompt 的优化**服务，没有任何一篇做过「不同 prompt 的槽位一一对齐 / 共有位点比例 / 共识序」。
- **方法论最近的是 PhyloLM**：prompt 当 gene、输出 token 当 allele、等位比例相似度 → NJ 树——**但树长在模型上，不是 prompt 上**，要横移一层。
- EoT 的「genome」是**搜索表示**不是**比较编码**；ConGrs 有 MSA 算法但比对对象是同一模型的多次**回答**；SPDeconstruction 在同一语料上做了拆解与聚类，但聚类在连续 embedding 上、位点是固定人工分类。

★ **负向检索证据**（这是本轮最硬的一条「空白」证明）：在 arXiv 全库检索
`abs:"prompt" AND abs:"multiple sequence alignment"`（唯一命中是蛋白 MSAGPT）、`abs:"prompt" AND abs:"consensus sequence"`（0 命中）、`abs:"prompt" AND abs:"phylogenetic"`（无 prompt 本体相关）、`abs:"prompt" AND abs:"motif"` + alignment（0 命中）
⇒ **没有任何论文对 prompt 集合做过 MSA / 共有位点比例 / 共识序 / prompt 系统发育树。**

**Q2：有没有自动发现维度集的工作？**
**有四条真实路线，但都不是「从一批 prompt 归纳共享位点表」。**（详细见 §3.11）
- **① 语料→多维 taxonomy**：TaxoAdapt（ACL 2025）——**维度名人工给，节点全自动**；
- **② 失败案例→反向长维度**：Auto-Prompt Ensemble——全自动，88→40→16 维；
- **③ 实例→隐式评测标准**：EvalAgent（COLM 2025）——全自动，专门产出「prompt 里没说但人会在意」的标准；
- **④ 神经表征→离散主题**：SAE-TM（ICML 2026）——SAE feature 天然是 thematic atom，可合并成任意数量主题；
- （外加 MDPI 2026 的两段式 LLM 聚类，**但自报簇数重复跑差 15%**。）
- prompt 域：**PromptPrism 明说自己是 top-down 手工的**；**DelvePO 自陈「dynamic component discovery 仍是空白」**；MAP-Elites 的 trait 是**人工描述子**；prompt 数据集综述的 63 维也是人定特征。
⇒ **修正后的准确说法**：**P2 不是「没人做过」，而是「做过的都在别的域（论文 / 奖励模型 / 写作任务 / 语言模型内部），且维度名或本体字段都还是人工前提」。** 我们的位置 = **把其中一条路线搬进「跨厂商 system prompt 语料」，并让维度名本身也自动产生**。

**Q3：有没有共识序 / 家族聚类（prompt 域）？**
**没有直接先例。**（检索证据见 Q1）
- 生物信息学侧标准工具齐备（Needleman-Wunsch / Clustal / 共识序列 / 系统发育树），ConGrs 已把 NW 搬进 NLP；
- EoT 的 C-Evolve 有「共识组投票」，但那是**投票选优**，不是**共识序列排序**；
- SystemPromptDeconstruction 生成了 dendrogram（自称 family tree），但树长在 SBERT 连续向量上，不是离散位点；
- PhyloLM 确实建了 NJ 树，但**树的对象是模型**。
★ **工具链可以整条搬过来**：Biopython `Align` / ClustalW / RAxML-NJ / motif 挖掘（MEME）都能直接用，**必须自研的只有「符号化 + 对齐层」**。
★ **另有一条新证据**：**「位点级 diff」至今无人做**——主流 prompt 平台（Langfuse / PromptLayer / Agenta）全部只有文本 diff，语义 diff 只在 0–9★ 的个人仓库里。而位点级 diff 是**位点 schema 一旦成立就白送**的能力，属于框架的边际收益。

**Q4（新增）：有没有「条款级 + 标注强制 / 散文」的成熟做法？**
**在法律域有，且整套可搬；在 prompt 域是空白。**
- **ARCCS**（EMNLP 2026 SysDemo）：层级分段 → **原子条款 typed tuple** ⟨法律功能, 主体, 适用范围, **强制条件集 M_i**, 原文指针⟩ + **显式过滤纯定义/描述/上下文条款**；GDPR 100 条，judge 一致率 90–96.67%、Fleiss κ=0.69。
- **CUAD**：41 类人工条款类型。
- prompt 域：From Prompts to Templates、Prompts in the Wild 只做**结构/位置**分类（Role/Directive/Example…），**不区分强制条款与叙述散文**；Instruction Hierarchy 的层级是**权限优先级**不是条款类型。
⇒ **「system prompt → 带类型标签、且标注强制/叙述的条款列表」这个具体产物，目前是空白** —— 这是我们上一轮用「章节级措辞扫描」硬做的那一块，现在有了可搬的现成形状（§3.13）。

## 6. 框架草案（本报告提出，非既有事实）

### 6.1 三层

```
L1 发现层 Discovery ──────────── 输入：一批 prompt
   ① 条款原子化      抄件#1/#2（SPDeconstruction 提示词）
   ② 候选维度归纳    抄件#9（两段式 LLM 聚类）+ 稳定性闸（自研#1）
   ③ 位点候选表      每位点：名称 · 定义 · 例句 · 稳定性得分

L2 编码层 Encoding ──────────── 输出：基因序列
   ④ 位点 schema 定稿  位点 / 等位表 / 模态(必须|应当|禁止|许可) / 强度 / 缺位语义 / 证据指针
   ⑤ 取值器            每条 prompt → 每位点上的 (等位, 强度, 证据 span)
   ⑥ 序列化            抄件#7 的 alpha6 思路 + 抄件#4/5 的规则基线做交叉校验
   ⑦ 双口径报告        覆盖广度 × 约束强度（上一轮结论，业界三家都没有）

L3 对齐层 Alignment & Evolution
   ⑧ 逐位点对齐        抄件#8 的 NW + 抄件 MNN 配对
   ⑨ 共识序            自研#4
   ⑩ 家族聚类          自研#5（存在集 Jaccard）
   ⑪ 变异/晋级/回滚    抄件#6 的三个重写当变异算子 + AgentNodes 三层基因组当晋级门
```

### 6.2 十个必须显式做出的设计决策（每条附业界依据）

1. **发现层与编码层解耦，先跑编码层。** 用 SPDeconstruction 已拆好的 38 个 JSON 直接跑通「schema → 取值 → 序列 → 对齐」，**再**回头做自动发现。依据：P2 是最上游、最不稳的一环，先做它会让整条链无法验证。
2. **位点 schema 与取值器分离**，且 schema 必须**可版本化**。依据：phenome 的四种编码里只有一种有逆解码 ⇒ 编码格式要有多个形态但**只有一位真源**；跨coders 的「shrinkage 伪影」同源。
3. **「未识别」是取值器的一等状态**，不许兜底成某个默认等位。依据：Prompt Genome 明说自己遇到怪句就回退 context 并标「no strong signal」——它把这个限制写在 README 里，我们要把它升级成设计。
4. **对齐必须用互最近邻而不是全局 1:1**。依据：Cross-Architecture Steering 第一版用 Hungarian 得到 68.4% 过阈率，作者复盘认定**虚高**（预选 top-K 抬高了判据、无向池化掩盖断层），换 MNN 后降到 45.5%，并写明「45.5% 是更诚实的估计」。
5. **发现层必须带稳定性闸，且闸不过就报失败**。依据：MDPI 2026 自报「温度 0.3 下簇数重复跑最多差 15%」。
6. **家族树必须配「打乱位点的 null 树」作负对照**。依据：prompt 语料大量互相派生，「共享同一模板」会造出假家族；真实树必须显著优于 null 才敢报家族。**这一步业界没人做，但它是家族聚类能不能站住的前提。**
7. **provenance 是框架的一部分，不是日志**。依据：现有工作几乎都假设 prompt 是独立样本，**没有一篇处理 prompt 之间的亲缘关系**——而亲缘关系正是我们要聚类的对象，所以来源/版本/时间戳/抽取模型必须进 schema。
8. **取值器走双通道**：软通道用 MICoL 式零样本多标签（给「疑似 / 未识别」连续分数），硬通道用 IFEval 式可执行 verifier（能形式化的位点必须有 checker）。依据：§3.12。**「未识别」必须能表达，不能兜底成默认等位。**
9. **模态 / 强度 / 作用域三字段自研，且是位点 schema 的一等公民**。依据：§3.15(d) —— Colang、Guardrails、PromptSys、sinc-LLM 四套独立生态全都没有（§5.2 #11–12）。
10. **维度集必须自查三件事**：维度正交性矩阵（防 23 个维度是同一维度的 23 种说法）、维度数-收益曲线（防维度数拍脑袋）、维度质量四把尺（防发现出的维度不可用）。依据：§3.11 的三条可抄判据。

### 6.3 机检清单（自研工具自带）

- 维度发现：**重跑一致性**（N 次跑；**〔修正 2026-11-19〕**度量 = 全局 ARI + 逐位点成员 Jaccard 分级，见 [`unified-framework-design-20261119.md` §3.1](unified-framework-design-20261119.md)）
- 取值器：**回放一致性**（同 prompt 两次抽取逐字一致 / 温度 0）+ 抽取模型版本记录
- 每条取值：**证据指针非空且 span 能回查原文**
- 对齐：**缺位与未取值可区分**；不允许出现「没有任何厂商取值」却仍出现在表里的位点
- 序列：**全局唯一性**（不同厂商不得有完全相同序列，除非人工签字）
- 报告：**覆盖广度与约束强度分列**，并注明强制度只是代理指标（抄 phenome 的 68% 坦白）
- 家族聚类：**存在集 Jaccard**，且 k=2 退化必须显式报告
- 家族聚类：**null 树负对照**（打乱位点后重建），真实树须显著优于 null
- 每个 prompt 的 **provenance 四元组**（源文件 / 版本 / 抽取时间 / 抽取模型）齐全
- 每个位点取值带 **模态 / 强度 / 作用域** 三字段，缺一判失败
- **维度正交性矩阵**存在且最大 \|Spearman\| 可报
- **维度数-收益曲线**存在（不是只报「用了 23 个」）
- 全文：**不得出现未读一手源就写实的数字**

## 8. 下一轮建议

1. **先跑编码层**：用 SPDeconstruction 已拆好的 38 个 JSON，跑通「位点 schema → 取值 → 序列 → 对齐 → 家族聚类」，把我们的 23 维先验当**假设**而不是**前提**，看自动对齐的结果能不能复现出相近的维度集（**这是对上一轮结论的一次外部验证机会**）。
2. **再攻发现层**：把 MDPI 的两段式聚类改造成 prompt 域版本，**第一件事就是量稳定性**（重复跑差多少），不达标就不往下走。
3. **与本项目 AgentNodes 的三层基因组对接**：Tier 0 = 冻结的不变量（底线基因），Tier 1 = 行为工件（可晋级的位点组合），Tier 2 = 研究产物（配置/因子）。⇒ 我们的「基因序列」天然是 **Tier 1 的表示形式**，而「变异 + 晋级 + 回滚」可直接用 SPDeconstruction / phenome 的现成算子。
4. **★ 把本轮新发现的四个件立刻接进框架**（都是现成的、能省一整轮自研）：
   - **ARCCS 的原子条款 typed tuple** → 直接当**位点 schema 的形状**（⟨语义类别, 主体/适用范围, 强制条件集 M_i, 原文指针⟩），把我们上一轮「按章节扫措辞」的做法升级成**结构化字段**；
   - **MICoL + IFEval/AutoIF 的双通道** → 直接当**取值器**：软通道给「疑似 / 未识别」连续分数，硬通道给可执行 checker；
   - **prompt-vc 的 sha256 行锚点** → 直接当**位点的证据指针与 provenance 层**；
   - **PromptGenome 的 GenomeMutator + AutoAPC-Select 部署门** → 直接当**演化层（L3 ⑪）的原型**，与 AgentNodes 的晋级门对接。
5. **★ 补两条本轮新出现的自研项到规格里**：**null 树负对照**（家族聚类的可信度前提，业界没人做）与**条款 ID ↔ 评测分数的关联键**（位点必须能挂到行为分数上，否则只是描述不是基因）。这两条都必须在第一版编码层就留出字段，**后补要重做全部数据**。
6. **行为层验证仍未做**：整套框架目前只能产出「描述型基因」，**不能证明「强制度条款真的被执行」**。若要做行为层对照实验，最现成的起点是 **AutoIF 的「label → verification function」** 与 **ARCCS 的 judge 一致率 / Fleiss κ** 口径（不要自造评测尺）。
