## 3. 当前共识与决策队列

**已定案**（详见 #6 汇总锚点 §3）：系统形态 = trace 绑定版（规则=基因、trace=行为轨迹、归因=只读 join、零新存储）；三条铁律（零平行账本 / 零新增 ID 体系 / 观测者≠被检方）；M1–M3 分期机检验收；不做清单三条。

**决策队列**（拍板顺序建议，详见 #5 §10）：

| 序 | ★ | 问题 | 分歧点 |
|---|---|---|---|
| 1 | **B6** | 转录语义 | snapshot 审计存照（便宜） vs 按 task_signature 选择性转录（牵动 harness_resolver） |

## 4. GRL ↔ 规则基因组的 schema 接口

GRL（#7）是条款级**等位层**的可执行实现，与 #5 设计的 registry schema 对齐点：

| GRL 字段 | 本设计对应 | 备注 |
|---|---|---|
| `id`（R-ANTH-SAF-0007 式稳定 ID） | `rule_id` | 条款 ID ↔ 评测分数关联键（自研 #13）的两侧 |
| `tier`（0/1/2） | `TIER1_COMPONENTS` 分层 | Tier 0 不可覆盖 = 编译器硬规则 |
| `locus`（D01–D23） | 位点表 | 「未识别」null 均为一等状态 |
| `modality` + `negation` | 模态字段（MUST/禁止） | GRL 六模态 + 三态否定更细 |
| `eval: [...]` | scorecard 关联键 | 行业空白点的双侧实现 |
| `provenance` | provenance 四元组 | 来源/版本/时间戳链路 |

★ **B6 拍板时必须把 GRL 规则对象拉进 schema 对照**——GRL 的 `scope`/`addressee`/`condition` 字段可能直接回答「选择性转录按什么切」。
