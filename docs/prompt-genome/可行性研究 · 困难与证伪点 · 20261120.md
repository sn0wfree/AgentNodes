# 规则基因组 · 可行性研究（困难与证伪点）

> **问题**：整个想法（规则=基因 → trace 绑定 → 归因三法 → 三回路进化）**到底能不能做成？难在哪？什么情况下该停或降级？**
> **方法**：仓内事实直读 + 既有五份调研的数字复用 + 本轮新增三路外部检索（judge 偏差 / 指令遵从实测 / 评测方差）。
> **状态**：研究稿（2026-11-20）。上游：[`unified-framework-design-20261119.md`](unified-framework-design-20261119.md)（UPGF）及其 §3.1（U4 已拍板）。

---

## 0. 总判定：三线分立

| 线 | 判定 | 一句话依据 |
|---|---|---|
| **工程可行性** | **高** | 底座已在仓内真实运行：TraceWriter（crash-safe JSONL + iter/call_id）、EventV2、GenomeVersionStore、validation_gate、batch_gate 8 步进程外门禁、70 golden、R-* 规则结构完整。M1 只是「解析 + 落点 + 校验」，无新科学 |
| **科学可行性** | **中** | 归因有效性是最大未知：本底表达（权重先验本来就会）、多效性/上位性（多对多）、指令拥挤反效应（加规则可能降性能）。**但每条都有已知的缓解路径或降级出口**（§3） |
| **经济可行性** | **取决于裁剪** | 全量敲除（50 规则）≈ 1500+ 次 agent 会话——不可行；裁剪到 top-10 ≈ 180–300 次——可行；表达谱/judge 走抽样——可行 |

**一句话**：这不是「能不能建成」的问题——**M1/M2/W1 几乎必然能建成**；真正的赌注在「建成的系统测出来的东西**可不可信**」（§3 假设 A1–A4）。每个假设都配了**便宜的证伪实验**，先证伪再全量，是本可行性研究的核心建议。

## 2. 十大困难（按严重度排序）

### D1 · 归因有效性天花板（科学层 · 最严重）
规则→行为是**多对多**：一条规则影响多段行为（多效性），一段行为由多条规则 + 权重先验 + 上下文共同决定（上位性）。**观测到的「遵守」可能只是权重先验本来就会**（本底表达）——phenome 作者自曝 68% 只是方向偏移不说明遵守，是同构警告。
**缓解**：敲除法 + 本底对照（设计已含）——这正是敲除是 gold standard 的原因。**残余风险**：合成致死（单敲无表型 ≠ 无用，D13 未决）→ 结论边界必须写成「单敲条件下无效应」。

### D2 · 量具可靠性（测量层）
LLM-as-judge 有三大量化偏差：**位置偏差**（系统性偏特定位置，[Shi 2025](https://arxiv.org/html/2410.02736v1) 系列引用 512）、**自偏好**（[Wataoka](https://openreview.net/forum?id=Ns8zGZ0lmM)，引用 419）、**冗长偏差**；上轮已有 κ 0.25–0.29（EvalAgent）。
**缓解（业界标准）**：交换位置、去偏 prompt、长度归一——judge 通道**带校正协议才可开通**（C10 校准样本集制度的具体内容）。script/regex 通道不受此影响——**这也是通道矩阵把 script 放第一的原因**。

### D3 · 统计功效与实验爆炸（实验层）
评测方差实测：run-to-run 噪声约占方差 **~30%**（[arXiv 2509.24086](https://arxiv.org/html/2509.24086v1)）；小评测集**检测不到几个百分点以下的差异**。70 golden 的检测下限 ≈ 5–10 个 case 的差异——**大多数规则影响不了这么多 case**。
**缓解（本轮新得出）**：敲除的**主表型改为「触发场景集」表现**（每规则 ≥3 个定向场景），而非 70-golden 全局分——更灵敏也更便宜；全局 golden 只做回归防线（敲除不该弄坏别处）。

### D4 · 指令拥挤反效应（本轮新发现 · 设计级）
OpenAI 社区实测反模式：**向 system prompt 堆叠多条指令可能降低整体表现**——即使约束看似有益。⇒ 规则的边际效应**可正可负**；规则条数是**有限资源**（密度预算）。
**影响**：① 敲除实验的 Δeffect 分布预期要双向（有的规则敲掉反而变好）；② **给 ★B6（选择性转录）添了独立理由**——全文注入不是浪费信息量的问题，是**拥挤降性能**的问题；③ 新设计项：规则密度预算（AGENTS.md 同时在场规则数上限）。

### D5 · 位置效应（本轮新发现）
2026 实测：system prompt **前 ~200 token** 内的指令合规率显著更高。⇒ 注入位置是未建模变量：AGENTS.md 在装配 prompt 中的位置（头部/尾部/中间）本身影响所有规则的表达强度。
**影响**：genome_snapshot 需补「注入位置」字段；否则跨会话比较混入位置混杂变量。

### D6 · 奖励黑客观测层（对抗层）
观测结论进入晋升决策后，被检方有动机**表演遵守**（perform compliance）。防线已在设计（观测者≠被检方 + 进程外 + append-only），但 judge 通道天然可被对抗（措辞规避 regex、迎合 judge）。**残余风险**：接受——把 judge 结论降级为「线索」而非「判定」。

### D7 · 成本（经济层）
敲除全量 = 50 规则 × 3 场景 × 2 臂 × N3–5 ≈ **900–1500 次 agent 会话**——不可行。裁剪：表达谱先跑 3 个月（M2 便宜）→ 只对 **top-10 承重/存疑规则**做敲除（180–300 次）→ 可行。judge 通道只对 script/regex 覆盖不到的 L0 散文原则抽样（~10 条），不做全量。

### D8 · trace 膨胀与 GC（工程层 · 已查证 2026-11-20）
每会话 +1 snapshot + N 条 rule_check。**E18 查证结果：trace 无 GC/保留机制**——TraceWriter 只追加，storage 侧唯一命中为 SQLite `auto_vacuum=INCREMENTAL`（物理回收，非保留策略）。M1 动工前需补保留决策（policy：不删 vs 按大小轮转）。

### D9 · 解析器脆弱性（工程层）
AGENTS.md 是 gh-gist 托管、网页编辑器人工维护——格式漂移概率不低。**已对冲**：解析失败 = fail loud（设计已定）；registry.json 入库后 CI diff 可见。**残余风险**：低。

### D10 · 自我参照（哲学层 · 务实可解）
观测系统本身也是被 AGENTS.md 约束的产物——「用基因组工具研究基因组工具」的套娃。**务实解**：v1 显式豁免——观测系统开发遵循同一治理流程，但**不纳入自己的观测范围**；待 v2 稳定后反身打开。

## 3. 关键假设与证伪点（先便宜证伪，再决定全量）

| # | 假设 | 证伪实验（成本从低到高） | 若证伪的降级出口 |
|---|---|---|---|
| **A1** | 规则文本对行为有**超出权重先验的边际效应** | **先导敲除**：选 1 条高表达规则（如 R-002）× 3 触发场景 × {原版,敲除版} × N3 ≈ **18 次会话**。Δeffect 全 ≈0 且本底对照无差异 → 假设存疑 | 系统降级为**合规审计工具**（registry + 违规阻断仍有价值）——价值重定位，不是项目失败 |
| **A2** | 行为可被机检锚定（script/regex 覆盖率） | M2 试点 3 条规则时实测：锚点查准/查全 + 覆盖规则比例 | 覆盖 <50% → judge 通道提前上线（带 D2 校正协议）或退纯人工抽查 |
| **A3** | 统计功效可负担 | 先导敲除时顺带实测方差 → 算出真实 n | n > 20/臂 → 敲除只做 top-5；触发场景表型替代全局 golden（D3 缓解） |
| **A4** | judge 校正后可用 | judge 试点先跑**校准样本集**（已知对错 50 条）测 κ | 校正后 κ 仍 <0.5 → judge 通道砍掉，script/regex/human 三通道足够 |

**建议的执行顺序**：M1（工程，无风险）→ **A1 先导敲除（≈18 次会话，最便宜的 go/no-go）** → 决定 M2/M3 全量还是裁剪。W1 与此完全并行（独立价值）。A1 的触发场景从转化表（#13）**对抗型 + 边界值型**取——电容实验（S2）：压应力下最可能显效。

### 3.1 科学维度补充带来的判读修正（2026-11-20 · 详见 #12）

1. **A1 判读标准修正**：通道化（Waddington；Wagner 1997）预测单敲 null 是**常态**——null ≠「规则无用」，判读为「被缓冲」；只有「原版与敲除版在压应力场景也无差异」才支持降级结论。
2. **触发场景必须含压应力型**（电容实验范式，Rutherford & Lindquist 1998）：边缘输入 / 对抗 / 资源紧张，不只常规路径。
3. **敲除对照逐字节同格式**（FormatSpread 76 分噪声地板，Sclar ICLR 2024）：唯一 diff = 被敲规则本身；格式进受控变量。
4. **遵守率正名为外显率**（penetrance，Kingdom 2022）——表达谱报表术语随之更新。
5. **E18 已查证（本日）**：trace **无 GC/保留机制**——TraceWriter 只追加，storage 侧仅 SQLite `auto_vacuum`（物理回收非保留策略）。M1 动工前需补保留决策（不删 vs 按大小轮转）。

## 4. 最小可信版本（MVP）与价值下限

**MVP = M1 + M2（script/regex）+ top-5 敲除 + W1**，其余相位按 A1–A4 证伪结果决定。

**价值下限论证**（即使科学层全部证伪）：
- registry + trace 绑定本身 = **可审计性基建**：每条规则可回查「哪次会话、哪个行为点、谁判定的」——这直接服务理念七与既有门禁体系，不依赖归因科学成立；
- W1 的 5526 条款 GRL 编码 = 跨厂商可比坐标系，独立可用；
- 敲除即使只跑 top-5，产出的「必需条款集」也直接服务 U4 的退役流程与 AGENTS.md 减法决策。

**价值上限**（科学层成立时）：规则效应量可测 → 晋升数据化 → AGENTS.md 演化从人工评审进入证据驱动——即上轮调研自研 #13 在自家仓库的全链落地。

## 6. 结论

1. **先建 M1 + 跑 A1 先导敲除（≈18 次会话）**——这是全项目最便宜的 go/no-go，两周内可完成，结果直接决定 M2/M3 的全量/裁剪/降级；
2. **W1 并行启动**——独立价值、零依赖、顺带复验 GRL 自述；
3. **judge 通道不预开通**——先 script/regex，judge 等 A4 校准样本集跑过再说；
4. **★B6 的筹码变重了**——指令拥挤反效应（D4）给了选择性转录一个性能层面的理由（不只是观测信息量层面），拍板时两条一起定。
