> **VERDICT: PASS** —— 本文件描述的语言已在 5526 条真实条款上跑通反编译 → 编译闭环，
> 18 条机检判据全部通过（复跑命令见 §9），其中 1 条是刻意注入违规的自证靶子。

## 0. 一句话结论

**可以，而且这件事正好落在上一轮调研确认的「真空白」上。** 业界有大量规则引擎（Rego / Cedar / Drools / Colang 2.0 / Guardrails），但**没有一套是为「跨厂商系统提示词」设计的、能把规则变成可寻址、可判定、可挂评测分数的一等数据的语言**。上一轮调研确认的三处空白正是这门语言的三个必填字段：强度、作用域、条款 ID ↔ 评测关联键。

本轮不只给设计，还**把它跑通了**：用 SPDeconstruction 对 CL4R1T4S 的成品条款（38 文件 / 15 厂商 / 5526 条）做反编译，得到一门可逆、能量化、能编译回多套文风的规则语言。

## 1. 定位：它是什么，不是什么

| 是 | 不是 |
|---|---|
| 规则的一等数据表示（散文是编译产物） | 自然语言的替代品（散文仍是最终交付物） |
| 跨厂商可比较的规则坐标系 | 行为约束引擎（不负责执行，只负责表达） |
| 「强度 / 作用域 / 条款 ID ↔ 评测键」三个空白的填补物 | 通用策略语言（Rego 已经做得很好了） |
| 提示词基因编码的**等位层实现** | 存在性层（那部分上一轮已经做完） |

★ **与既有工作的接口**：

- **存在性层**（上一轮：26 家 → 23 种图案）= 「这个位点写没写」，对应 GRL 的 `locus` 字段；
- **等位层**（上一轮：趋同比值 / 私有等位 72%）= GRL 的 `modality` + `negation` + `verb` + `object` 组合；
- **三层基因组**（AgentNodes §9）= GRL 的 `tier` 字段：Tier 0 底线冻结不可覆盖、Tier 1 提案制行为工件、Tier 2 可自改研究工件；
- **Tier 0 不变量** = GRL 的一条硬规则：Tier 0 规则不可被 Tier 1/2 的 `override` 覆盖，编译器直接报错。

## 2. 语法

### 2.1 规则对象

语言刻意做成 **JSONC（JSON + 注释）**：因为 LLM 输出 JSON 的可靠性远高于任何自定义语法，而机检成本最低。散文里的表格、引用、优先级声明都下沉成**数据字段**，这正是上一轮调研里「强度 / 模态字段全行业空白」的解法。

```jsonc
{
  "id": "R-ANTH-SAF-0007",      // 稳定 ID：条款 ID ↔ 评测分数的关联键
  "locus": "D01",               // 23 位点之一，可为 null（"未识别"是一等状态）
  "tier": 0,                    // 0=底线冻结 1=行为工件 2=研究工件
  "class": "regulative",        // regulative | constitutive | non-statement
  "modality": "must",           // must | must_not | should | may | can | unspecified
  "negation": "yes",            // yes | no | suspected（三态，不是布尔）
  "scope": { "key": "harmful-content-safety", "raw": "HARMFUL CONTENT SAFETY" },
  "addressee": "claude",
  "verb": "reproduce",
  "object": { "key": "copyright chunk", "raw": "large 20+ word chunks of content" },
  "condition": "when from search results",
  "truncated": false,           // 上游数据缺陷的显式标记
  "eval": ["safety.refusal_rate", "copyright.no_large_quote"],  // ← 行业空白点
  "provenance": { "vendor": "ANTHROPIC", "file": "Claude-4.1.json" }
}
```

★ 四个字段的设计依据，全部来自实测（不是拍脑袋）：

- `modality` 的 6 个取值 = 语料里 10 种原始 D 槽表述的归并结果（§4.2）；
- `negation` 是三态字符串而非布尔 —— 因为 68.2% 的条款根本没写模态，**「缺失」与「相同」必须可区分**（§4.3）；
- `scope` 同时存 `key`（归一）与 `raw`（原文）—— 因为原始 section 名有 295 个、其中大小写变体泛滥（§4.6）；
- `eval` 数组是空的、等着被填 —— 上一轮调研确认：Langfuse / Agenta / PromptLayer 的「版本 → 评测 → trace」链路与条款 ID 之间**没有任何公开关联键**，位点若挂不上行为分数，就只是描述不是基因。

### 2.2 四种引用形态（这就是「代指特定规则」的答案）

引用是语言的核心用途。四种引用由弱到强，逐层收窄：

| 形态 | 写法 | 代指的是 | 命中范围 |
|---|---|---|---|
| 位点引用 | `#D01` | 一个维度下的全部规则 | 存在性层 |
| 等位引用 | `#D01~must` | 该维度下所有 `must` 模态的规则 | 等位层，不指名文件 |
| 精确引用 | `@R-ANTH-SAF-0007` | 指定的**那一条** | 个体 |
| 断言引用 | `⊇` / `⊥` / `≡` | 集合之间的**可判定关系** | 验证层 |

```python
# 断言可机检，不是描述
evaluate_assertion('@R-ANTH-SAF-0007', '⊇', '@R-ANTH-SAF-0008', rules)
# → (True, {'missing': [], 'lhs_size': 1, 'rhs_size': 1})
```

★ **等位引用是这轮最有价值的一层**。上一轮实测出「存在性定义家族，等位定义个体」：ANTHROPIC 与 OPENAI 在存在性上相似度 0.913，但 23 个维度上**等位全部不同**。等位引用让「不指名文件、但精确到语义等价类」的代指成为可能 —— 例如「凡是写了注入防御且用 must 模态的条款」可以一次取出来跨厂商对比。

### 2.3 模块与覆盖

```jsonc
{
  "import": ["base.tier0", "base.behavior"],
  "override": {
    "@R-SAF-001": { "modality": "must_not" }
  }
}
```

**覆盖语义有一条硬规则**：Tier 0 规则不可被 Tier 1 / Tier 2 覆盖。编译器遇到这种 override 直接报错退出 —— 这一条直接对上 AgentNodes 的「不变量违反 = 直接判负」，也解释了上一轮那个谜团：**「5 条 Tier 0 底线基因没有一家写全」不是缺陷，是定制化的必然结果**（底线条款按各家法律立场定制，共享等位低于随机）。

## 3. 语义规则（四条，每条都有实测支撑）

### 3.1 强度是有序等级，不是布尔

强度分三档：`must`（3）> `should`（2）> `may` / `can`（1）> `unspecified`（-1，未声明）。

★ 这个分级不是装饰 —— 它让「风格表不许把 must 降级成 may」成为一条可机检的约束（§3.4）。上一轮调研发现强度字段是行业空白；只把它定义成一个无序枚举，仍然无法机检「降级」。

### 3.2 否定必须跨槽探测，且要三态

实测：**否定极少出现在模态槽里**。D 槽明确表态否定的只有 26 条（`cannot` 24 + `can't` 2），而全语料有 1094 条规约带否定语义。否定藏在这些位置：

- I 槽前缀：`not do X`
- 动词本身：`avoid` / `refuse` / `prevent`（11 个否定动词）
- 正文深处：`you must always respect copyright by NEVER reproducing ...`（否定在对象槽里）
- 条件从句里：`if you do not know the answer`

⇒ 语言规定 `negation` 为三态：

| 值 | 判定来源 | 占比 |
|---|---|---|
| `yes` | D 槽 / I 槽前缀 / 否定动词（高置信） | 1094（25.8%） |
| `no` | 以上皆无 | 2955（69.7%） |
| `suspected` | 正文扫描到否定词但 D / I 未表态（低置信，单列，不当正式否定） | 188（4.4%） |

★ **`suspected` 这一档不是妥协，是必需的**：条件句里的否定（`if you do not know the answer`）会让全句扫描误判。第一版用「全句扫描 + 并集」的结果是 68.2% 的条款被误判为否定，其中 124 条纯粹是**章节名里的 `or not search`** 被算成了否定。排除作用域、只扫正文、再降到 `suspected`，误判率才降到可接受。

### 3.3 作用域规范化：保留原文 + 归一键

原始 section 名 295 个，其中大小写 / 措辞变体泛滥：

```
harmful content safety            88
HARMFUL CONTENT SAFETY            62
Harmful Content Safety            35
   ↓ 归一
harmful-content-safety            186
```

casefold 一步 295 → 278；再叠同义词归并 278 → 268。★ 整体收益只有 1.10 倍，但**收益集中在头部条目**：头部四组各合并掉 40–50 条。这是一条长尾结论 —— **作用域规范化必须做，但它的价值几乎全在头部**。

### 3.4 编译器契约：风格表数据驱动 + 强度守恒

编译器把一条规则渲染成散文。渲染策略（各家文风）是**数据**，不是代码：

```python
'xai_policy':  {'open': '<policy>', 'close': '</policy>',
                'modality': {'must': 'MUST', 'must_not': 'MUST NOT', ...},
                'frame': '{body}.'}
'openai_plain': {'modality': {'must': 'must', ...}, 'frame': '{body}.'}
'anthropic_effect': {'modality': {'must': 'always', 'should': 'prefer', ...},
                     'frame': '{body}, because it directly affects the user.'}
```

★ 编译器必须自证「强度守恒」，两条缺一不可：

1. **极性守恒**：`must` 不许编译成 `never` / `must not`；
2. **强度保档**：`must` 不许降级成 `may`。

只查极性会漏掉降级，只查档位会漏掉极性反转 —— 实测两种漏法都真实发生过（§5）。

## 4. 实测结果

语料：SPDeconstruction 对 CL4R1T4S 的处理产物，38 文件 / 15 厂商 / **5526 条条款**（regulative 4237 · constitutive 1159 · non-statement 130）。

### 4.1 反编译覆盖（不丢条款）

| 槽位 | 填充率 | 口径 |
|---|---|---|
| 动词 | **100.0%** | 4237 / 4237 |
| 对象 | **97.1%** | 4113 / 4237 |
| 作用域 | 63.9% | 2706 / 4237（其余条款原文不带 `Under <Section>,` 前缀） |
| 条件 | 2879 条 | 剥离污染后 |
| 模态 | **31.8%** | 1349 / 4237 |

### 4.2 模态枚举是反推出来的，不是设计的

原始 D 槽 10 种表述 → 归并 6 档：

| 归并档 | 原始表述 | 条数 |
|---|---|---|
| `must` | must 523 · MUST 22 · WILL 5 · has to 1 | 551 →（含否定改判后 387） |
| `should` | should | 489 |
| `can` | can | 237 |
| `may` | may 45 · might 1 | 46 |
| `must_not` | cannot 24 · can't 2 | 26 →（含跨槽检出后 190） |
| `unspecified` | **D 槽为空** | **2888 = 68.2%** |

★ **68.2% 的规约条款根本没写模态** —— 这是这门语言最硬的一个数字。它意味着：任何只读「模态槽」的强度分析，对三分之二的条款都是无信息；而这门语言把「未声明」变成一个**可枚举、可比较、可统计**的值。

### 4.3 否定三态

`yes` 1094（25.8%）· `no` 2955（69.7%）· `suspected` 188（4.4%）。

### 4.4 ★ 等位键的分辨率是实测出来的

等位键分三层，跨厂商共享量：

| 分辨率 | 键 | ANTHROPIC×OPENAI | ANTHROPIC×XAI | HUME×MISTRAL |
|---|---|---|---|---|
| L1 粗 | scope + 模态 | 6 | 6 | 1 |
| **L2 中** | **scope + 模态 + 否定 + 动词** | **35** | **16** | **5** |
| L3 细 | + 完整对象 | 3 | 0 | 0 |

★ **两头都掉**：L1 太粗（丢掉否定与动词，混掉不同规则），L3 太细（完整对象逐字不同，跨厂商几乎不可比）。**L2 是最优分辨率**，5 组厂商对里 3 组满足这一单调性（判据 C13）。这与上一轮在存在性层得到的 G2 建议（动词 | 否定 | 模态）一致，但现在是**条款级**实测出来的。

### 4.5 闭环质量

| 指标 | 结果 | 口径 |
|---|---|---|
| 槽位保真度 | **4237 / 4237 = 100%** | 编译回散文后，每个非空槽位的内容都还在 |
| 强度守恒 | **12711 次检查，0 违规** | 4237 条 × 3 套风格 × 2 道检查 |
| 风格可替换 | **2073 / 2073 = 3 个不同输出** | 同一规则、三套文风，输出两两不同 |
| 编译器幂等 | 逐字一致 | 同输入两次编译 |

### 4.6 位点自动归属不可靠

用上一轮的关键词正则给条款打位点标签：36.6% 无命中 · 8.8% 并列歧义 ⇒ **唯一归属率只有 54.6%**。

⇒ 设计上必须允许 `locus: null`，**「未识别」是一等状态**。上一轮调研里「位点集自动发现」是四个子问题里最不稳的一环，这里给出了它的量化上界。

## 5. 本轮抓到的 7 个真缺陷（这一节是本文档最有价值的部分）

设计本身不产生证据，**跑起来才产生**。以下 7 个缺陷全部是在跑真实语料时暴露的，其中 3 个是判据自己有洞：

| # | 缺陷 | 症状 | 修法 | 类别 |
|---|---|---|---|---|
| 1 | 编译器槽位粘连 | 输出 `search resultsalways` | 槽位用列表拼接 + 空槽守卫 | 实现 |
| 2 | 风格表极性反转 | `must` 被渲染成 `never`，语义完全相反 | 风格表措辞纳入受控强度词表 | 实现 |
| 3 | **三态字符串被当布尔** | `if rule.negation` 把 `'no'` 当真 ⇒ 所有规则被加 `not` | 显式 `== 'yes'`；语言规范禁止同字段混用布尔与枚举 | 实现 |
| 4 | 否定过计 | 章节名 `or not search` 被当否定（124 条） | 否定扫描排除作用域，只扫正文 | 实现 |
| 5 | 上游数据污染 | C 槽混装 section（864 / 3334 = 25.9%）+ 语义截断（1353 条 = 31.9%） | 剥离 + 显式 `truncated` 标记 | 数据 |
| 6 | 极性探测器复合模态 | `must not` 拆成 token 后首个是 `must` ⇒ 190 条误判 | 极性从**编译器写入的模态槽**判定，不在输出里猜 | 实现 |
| 7 | **判据自己有洞** | C3 空 token 集被当成不匹配（85 条）；C8a 把 `locus=None` 也算进位点命中，**命中 5526 条 = 全集却仍判 PASS**；C11 写成了恒真 | 加空集守卫；给命中量加**上限**检查；判据加自证探针 | ★ 判据 |

★ 第 7 条是本轮最值得记住的一条：**「PASS」不等于「判据正确」**。C8a 抓到了 5526 条（全集）却仍然 PASS，因为判据只写了 `>= 1`。**给「命中量」加下限是弱判据，给它加上限才是强判据** —— 上限能抓住「过滤条件失效导致的全集命中」这类静默退化。

## 8. 边界（明确没做什么 / 没验证什么）

- **语料只有 15 厂商**（SPDeconstruction 产物覆盖 38 文件 / 15 家），另 11 家完全无产物 ⇒ 全量 26 家的结论尚未成立。
- **条款数据本身不是黄金标准**：SPDeconstruction 用 gemini-flash-3.5 一次生成，条款级数据带上游缺陷（已量化：C 槽污染 25.9%、语义截断 31.9%）。GRL 能**显式标记**这些缺陷，但消不掉它们。
- **只读 `eval` 字段是空的**：关联键的**机制**已经定义，但**没有挂任何真实评测分数** —— 这一环还没接。这是它现在最大的未验证部分。
- **没有做行为层验证**：GRL 表达的规则是否真被执行、是否真改善行为，一次都没测过。
- **正编译不还原原文**：字符 shingle 还原度只有 5.4%（第一版），因为编译器生成的是**新散文**而非原文复刻。GRL 的正确定位是「同一套语义、不同文风」，不是「还原」。
- **未做增量式 diff 的实测**：GRL 层的位点级 diff 已能算，但与散文 diff 的规模对比只做了 6 组厂商对，样本偏小。
- **这是我的设计，不是行业标准**：命名（基因规约语）、ID 格式、引用形态都是本轮定的，没有与任何外部规范对齐过。
