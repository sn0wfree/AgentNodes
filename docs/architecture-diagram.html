turn / runturn＝会话中被准入的一次执行权（串行单位，并行全在 turn 内）；run＝一次执行实例，子 run 挂在根 run 成树。派生 id 已在 SessionController 签发 ✅（{sid}#n → :r0）
mailbox会话内的等待队列——所有排队都发生在这，闸不排队 ✅
steer / followup / interrupt插话注入当前 run（安全点、只追加）✅ R2（fence 路由·合批·滞留晋升）/ 排队等下一 turn ✅ / 打断当前 turn ✅ B1（CancelScope 节点边界取消·无产物·栅栏释放）；级联取消整棵子 run 树 ⏹ 无子图节点（fanout 分支级联 ✅）
lane（通道）同 key 请求的专用串行道：session lane 保 turn 顺序 ✅；subagent:{session} 子代理通道（默认并发 8，不碰 mailbox 防自锁）⏳
cap 20 · 溢出 summarizemailbox 深度上限；满了把最旧的等待消息摘要化——全系统唯一拒绝点 ✅

容量组闸每类活的最大并发槽位（chat 宽 / study 窄=executor 池上限 / cron 隔离）；满→排队不拒绝，running 不抢占 ⏳
fence（栅栏）写权限认领（activeRunId）+ 提交校验：被取代/被取消的 run 陈旧产物不落库 ✅ R1 已挂根（claim→run→validate→release；被超越 emit run.fenced + settled{fenced:True}；INV-4 进注册表）
fold 重建重启后从事件流重放算出状态（恢复状态，不恢复执行——被打断的 run 标 interrupted，重试靠重提）✅ B2（turn 计数续号 · session 映射恢复 · run.interrupted 标记 · 幂等；mailbox 待办/幂等表不恢复=定稿明说）
grace关闭时给运行中 turn 的收尾宽限（默认 ~5 分钟，可配置），超时标 interrupted ✅ R2（stop_consumer(grace)）；fold 后标 interrupted ✅ B2
