# 前端配色审查报告（2026-11-24 · 手动操作 + 量化对比度 · 零代码）

> 状态：审查记录 + 修复建议。审查本身零代码；P0 语义色问题已由 `semantic-color-unification-20261124.md`（用户批准）实施完成，复测结果见文末。
> 方法：在 Vite 5173 实机切换 dark/light 双主题、逐页操作（/chat 消息流、模型下拉、/、/account、/login），
> 用浏览器侧脚本提取每个可见文本元素的实际前景/背景色（正确解析 `color(srgb r g b / a)` 与 `rgb()`），
> 计算 WCAG 对比度（正文阈值 4.5:1，大字 3:1）。对比度数值受多层半透明背景合成影响，作**参考**；
> 结论以"可定位的硬编码色 + 双主题对照"为准。

## 1. 总体结论

- **暗色主题基本健康**：/chat 仅 7 项低对比，多为 4.0–4.5 的边缘值；无结构性错误。
- **亮色主题明显偏弱**：/chat 有 53 项低对比，重灾区是**为暗底设计的亮色语义色硬编码**。
- **根因**：P1-1 令牌迁移只把 amber/warning 做了 9-token 双主题映射（B-2），
  但 **emerald / violet / rose / sky 等语义色仍是 Tailwind 固定色阶硬编码**，全项目 60+ 处。
  这些亮色（如 `emerald-400` #34d399、`violet-300/70`）在暗底上合适，在浅底上对比度 1.4–2.6:1，远低于 4.5:1。

## 2. 具体问题（按严重度）

### P3 · 非配色问题（顺带记录）

- `/account` 页「个人账号」标题出现两次（`PageShell` 的 Section h3 + `AccountSection` 自身 h3）——文案重复，非配色。
- 监控页（`/`）亮色下多处"工作区尚未就绪"错误文案（rose-400）——配色问题已列 P0，数据加载失败本身属环境（home 工作区未就绪）。
- 登录页配色合理（h1 ~10:1、label ~4.6:1、主按钮深底白字），无需改。
- 亮色主题下 `.bg-app` = `#fafafa`、CSS 变量 `--card:#ffffff`、`--foreground:#404040` 正确，**无暗色残留**。

## 3. 修复优先级建议

1. **B-3 语义色令牌化**（P0）：success/thinking/danger/trend 四组 token 双主题，替换 60+ 处硬编码 —— 收益最大，需独立方案 + 基线重录。
2. **次级文字色阶加深**（P1）：亮色 muted 文字从当前浅灰调到 ≥4.5:1。
3. **边缘色微调**（P2）：随 B-3 一并处理。
4. 「个人账号」标题重复（P3）另开小修。

## 4. 不做

- 本报告不改变任何代码/主题配置；所有修改待用户批准。
- 不把"对比度脚本的绝对数值"当验收唯一标准（多层透明合成有误差），以双主题实机观感 + 令牌一致性为准。
