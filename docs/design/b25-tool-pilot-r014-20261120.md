## 0. 目标与非目标

**目标**（对齐 roadmap WP-6 目标/验收行）：在所有前置验收后，把隔离执行试点从
B2.2 3c 的「write 工具 + 探针混合驱动」推进为**准入复核闭环 + 真实工具路径端到端**——

1. **准入复核**：回答 B2.3 §2.6 遗留的两条契约口径——worker 内 ctx 回调恒 None
   （isolatable 工具必须容忍）、worker 只注入 ctx 不注入 loop 的 kwargs 直注面。
   给出**不依赖工具作者自觉**的可操作判定，使「依赖回调/kwargs 直注却在 worker
   静默分叉」的工具在准入阶段被结构性拒绝；
2. **真实工具试点**：限定 `write`（WriteFileTool）到临时工作区，用真实工具路径
   覆盖端到端副作用边界、deadline、终止确认、迟到拒收、lease 顺序；
3. **发布说明口径**：准确区分「停止执行」与「副作用不可撤销」，不宣称进程终止
   可以撤销已写文件。

**非目标**：① **不接生产 AgentLoop 的通用隔离开关**——试点是脚本/测试级能力证明，
不是生产默认行为，生产接线属 B2.4；② 不接 shell（roadmap §6 #5 裁决：shell 延期，
不作为顺手扩展）；③ 不实现 POSIX 生产执行（禁启用不变）；④ 不扩大工具清单
（试点 allowlist 只含 `write`）；⑤ 不改 `ToolContext` / codec（B2.3 已验收） /
`isolation.py` 的已验收协议；⑥ 不宣称副作用可撤销；⑦ 不引入 per-call id 协议
（B2.4 域）。

## 1. 现状证据

**E1 · 准入只查 effects，且当前完全没有生产消费者。**
`check_isolation_admission`（`core.py:863-887`）只对 `timeout_capability == "isolatable"`
的工具生效，拒收集合是 `_ISOLATION_FORBIDDEN_EFFECTS = {"db", "net"}`
（`core.py:50-54`）；唯一的调用点是 `ToolRegistry.timeout_capability`
（`core.py:907-920`），不合规声明回落 `unstoppable`。四级能力常量在
`core.py:39-47`，默认 `unstoppable`（`core.py:577`）。实测 `git grep` 全树：
**没有任何 builtin 工具声明 `isolatable`**，准入门槛目前只被
`tests/test_tool_isolation_admission.py` 的合成探针测试驱动；3c 试点是直接调
`isolate_tool_call("write", ...)`（`test_isolation_pilot.py:41-44`），**从未经过准入检查**。
结论：B2.5 若只写一份「准入复核清单」而不把试点路径纳入判定，门槛仍是纸面契约。

**E2 · worker ctx 回调恒 None vs 进程内 kwargs 直注，是两条真实分叉。**
B2.3 codec 的 `WIRE_FIELDS` 只有 9 个纯数据字段（`_isolation_context.py:33-48`），
`to_wire` 从不读回调/对象字段（构造级 impossibility）；worker 侧 `_decode_ctx`
（`_isolation_worker.py:72-89`）解码出的 ToolContext 中 `emit_progress` /
`emit_event` / `permission_*` / `data_store` / `sandbox` / `before_execute` 恒为 None。
进程内 `_build_tool_kwargs`（`loop/tools.py:59-94`）则同时注入：
`workspace` / `session_id`（kwargs，:65-68）、`_progress_callback`（:69）、
`ctx`（:70-86，含全部回调）、以及按工具名注入的 `emit_event` / `message_id` /
`_subagent_count_ref` / `_parent_registry`（`task`，:87-91）与 `emit_event`（`todowrite`，:92-93）。
worker 的 `_run_tool` 只做 `tool.invoke({**args, "ctx": tool_ctx})`
（`_isolation_worker.py:92-105`），**不注入上述任何 kwargs**。此外 worker 走
`invoke`（:102）而非 `ainvoke`：生产 `ainvoke` 的 permission gate（`core.py:681-686`）
在 worker 内不存在，ASK 由父进程 `ApprovalProxy` 代理——这是第三条必须记录的语义分叉。

**E3 · 「只看 execute 签名」挡不住静默分叉——这是本方案的核心难点。**
实测三类真实工具形态：

| 工具 | execute 形态 | 回调依赖 | 纯签名检查能否发现 |
|---|---|---|---|
| `show_chart` / `show_report` | 干净显式签名 `(self, ctx, source_file, ...)`（`display_tools.py:157-163` / `:285-290`） | 函数体读 `ctx.emit_event`（`display_tools.py:229-230` / `:347-348`） | **不能**——签名无异常，worker 内 `emit_event is None` 被 `if` 静默跳过，图表/报告不进 SSE，调用却报成功 |
| `task` | `execute(self, **kwargs)`（`subagent_tool.py:166`） | `kwargs.get("emit_event"|"_subagent_count_ref"|"_parent_registry")`（`:187` / `:191` / `:227`） | **不能**——**kwargs 无显式参数；且 `_INJECTED_PARAMS`（`core.py:92`）只含 `self/ctx/workspace/session_id/_progress_callback`，不含这三个键 |
| `todowrite` | `execute(self, ctx, **kwargs)`（`todo_tools.py:167`） | `kwargs.get("emit_event")`（`:177` / `:205-209`） | **不能** |

即：回调依赖可能藏在函数体里，也可能藏在 **kwargs 里；`_INJECTED_PARAMS`
这份现成的排除集本身就不完整（缺 `emit_event` / `_subagent_count_ref` /
`_parent_registry` / `message_id`）。任何「工具作者声明我不需要回调」或
「签名里没有注入参数就安全」的判定都不可靠。判定必须结构化、可测试、默认拒绝
（详见 §2.1）。

**E4 · WriteFileTool 在两条路径下的行为差异与副作用边界。**
`WriteFileTool.execute(self, ctx, path, content)`（`file_tools.py:302`）：只读
`ctx.workspace`（:303-309）与 `ctx.write_roots` / `ctx.read_roots`（:341-345），
**不读任何回调、不读 kwargs 直注**。因此 worker 内行为与进程内一致——这正是它被选为
首试点的原因。边界有两层：① codec 的 Path→str→Path 强转在 worker 内由
`PathWhitelist.__init__` 的 `Path(workspace).resolve()`（`legacy.py:181`）吸收；
② 路径保护在 `resolve_write`（`legacy.py:187-202`）与 `_validate_basic`
（`legacy.py:238-268`）：绝对路径 / UNC / 盘符 / `~` 拒，`..` 逃逸由
`_resolve_under_workspace` 的 `relative_to` 检查拒（`legacy.py:285-301`）。
注意 **默认 `DEFAULT_WRITE_ROOTS = (".",)`（`legacy.py:149-151`）**——实际边界是
「整个 workspace 子树」，而工具 docstring 仍写 strategies/templates/memory/logs
（`file_tools.py:266-267` / `:293-295`），文档已过时；试点报告的副作用边界必须按
代码事实写「tmp_path 子树」，不得照抄 docstring。

**E5 · 3c 试点证明了什么、没证明什么。**
`tests/test_isolation_pilot.py`（win32 gate，:19-23）已验证：S1 真实 write 写
tmp 工作区成功（:33-47，`completed`/`stopped` + 文件内容断言）；S2 deadline 终止
并确认（:50-60，`terminated`/`stopped`、wall-clock < 6s）；S3a 迟到结果不归因
（:63-69）；S3b 常驻 worker 超时毒化后拒绝复用（:72-84）；S4 lease 事件序
acquire < confirmed < release（:87-104）。**但 S2/S3/S4 全部由测试探针
`probe_sleep`（`_isolation_worker.py:159-163`）驱动，不是真实工具路径**——与
WP-6 验收行「deadline / 终止确认 / 迟到拒收 / lease 顺序都由真实工具路径测试」
尚有差距（详见 §2.3 / §3 5b）。

**E6 · B2.4 前置关系。**
roadmap WP-5（B2.4）负责 deadline/E5、进程树终止、退出确认、迟到结果与 lease 的生产接合，
明确禁止「未确认退出就释放 lease」「超时后接纳迟到产物」「把进程终止描述成可撤销副作用」；
WP-6（B2.5）的前置是「B2.4 验收及单独批准 + 平台矩阵确认 + 工具准入与副作用清单审查」。
B2.4 之前试点无生产影响，可以严格拒绝；B2.4 之后准入复核必须变成注册表级 fail-closed
门禁，否则新增/改写的工具会在生产路径上静默分叉（详见 §2.4）。

## 2. 深模块设计

### 2.1 准入复核清单：不依赖作者自觉的结构化判定

**设计原则**：默认拒绝（deny-by-default）。不要求工具作者额外声明「我安全」；
由**试点 allowlist 的构造过程**做静态审查，并由 **CI 回归守卫**在工具源码变化时
自动使 allowlist 失效。三层判定按序执行，任一失败即拒绝 isolatable / 拒绝入试点：

**C1 · 声明面（现有，保留）**：`timeout_capability == "isolatable"` 且
`effects ∩ {"db","net"} == ∅`（`core.py:863-887`）。声明是**必要不充分**条件。

**C2 · 签名面（增补）**：用 `inspect.signature(tool.execute)` 检查是否显式声明了
`ctx` 之外的注入参数。注入参数集**不能复用 `_INJECTED_PARAMS`（`core.py:92`，已过时）**，
须以 `_build_tool_kwargs` 实际注入面（`loop/tools.py:59-94`）为事实源定义新常量
（建议 `ISO_INJECTED_KWARGS = {workspace, session_id, _progress_callback, emit_event,
message_id, _subagent_count_ref, _parent_registry}`，落在 `core.py` 邻近
`_INJECTED_PARAMS`，并让 `_INJECTED_PARAMS` 与之对齐——该对齐是独立小改，若审批
不允许触碰，则 5a 只在准入模块内定义 superset 并在测试中钉住两者差异）。
`**kwargs` 形态本身不因「未显式声明」而豁免——转 C3。

**C3 · 函数体静态面（增补，关键）**：对 `execute` 源码做 AST/行级扫描，拒绝任一：
- 读 `ctx.emit_progress` / `ctx.emit_event` / `ctx.permission_evaluator` /
  `ctx.permission_gateway` / `ctx.data_store` / `ctx.sandbox` / `ctx.before_execute`；
- 经 `kwargs.get(...)` / `kwargs[...]` 读取 C2 注入集中的任一键；
- 读 `retry` 之外的宿主属性（本阶段只需覆盖上述两类，其余属未来扩展）。
  实现可基于 `inspect.getsource(execute)`（全部 in-tree 工具可获取）；解析失败
  → **判拒绝**（fail-closed），不得判通过。此检查直接命中 E3 的
  `display_tools.py:229` / `subagent_tool.py:187` / `todo_tools.py:177`。

**C4 · 试点 allowlist（执行开关）**：试点是否启用按**工具名白名单**决定
（本批仅 `{"write"}`），而不是按 `timeout_capability` 声明决定——声明由工具作者
控制，allowlist 由审查者控制，这是「不依赖工具作者自觉」的最终落点。allowlist
的构造测试对每个入选工具执行 C1–C3，并对**全注册表**跑一次扫描生成「分叉风险清单」
（不阻断其他工具，只作为审查输入）；后续任何工具加入 allowlist 必须附 C1–C3 通过
证据与副作用边界说明。

**C5 · 回归守卫（CI）**：契约测试对 allowlist 内每个工具的 `execute` 源码做
指纹断言（或每批重跑 C2/C3）；源码一旦改为读回调/kwargs，测试当批变红，
强制重新审查。C4 + C5 把「一次性人工审查」升级为「持续结构保证」。

**判定结果落点**：`check_isolation_admission` 的返回语义不变（`None` = 可声明 /
非空字符串 = 拒绝理由，`core.py:866-869`）；C2/C3 增补为其中的拒绝分支，C4/C5
作为**试点层**的独立守卫（不塞进 `core.py` 的通用声明面，避免把试点策略泄漏到所有执行器）。
本批不改 `ToolRegistry.register` 行为（保持惰性查询，surgical）。

**诚实边界**：静态扫描不是形式化证明——别名（`cb = ctx.emit_event` 的间接形式仍在
源码里可读到）、动态 `getattr`、`exec` 生成的读取可能绕过；因此 C4 的显式
allowlist 才是执行依据，C2/C3 是**降低审查遗漏概率的结构化检查**，不得在文档中
宣称「自动证明工具无回调依赖」。

### 2.2 试点工具选择：WriteFileTool

**理由**：① 只依赖 `ctx.workspace` / `write_roots` / `read_roots` 纯数据字段
（`file_tools.py:302-345`），不读回调、不读 kwargs 直注（E4），在 worker 内与进程内
行为一致；② `effects = {"fs"}`（:300），过 B2.1 effects 门槛；③ 3c S1 已用真实
write 验证端到端写盘成功（`test_isolation_pilot.py:33-47`）；④ 路径保护是工具与
sandbox 的既有职责（`legacy.py:187-301`），试点不需要新增保护逻辑。

**副作用边界（按代码事实，不按 docstring）**：仅当 `ctx.workspace = tmp_path`、
`write_roots` 默认化时，写入落在 `tmp_path.resolve()` 子树（`legacy.py:181` / `:293` /
`:303-314`）；绝对路径 / UNC / 盘符 / `~` / `..` 逃逸由 `legacy.py:238-268` /
`:285-301` 拒绝；`ctx.workspace is None` 时工具直接返回 `err_actionable`
（`file_tools.py:303-308`，B2.3 契约「缺字段 → None，工具级处理」已验证）。

**终止不可撤销的诚实声明**：进程终止只能停止**后续执行**，不能回滚**已发出的
写盘**——deadline 命中时可能留下完整或部分文件；`write` 虽是幂等覆盖
（`file_tools.py:285` 自述），但幂等 ≠ 取消（WP-5 禁止项）。试点报告与发布说明必须
逐字写明「停止执行，不撤销已写文件」。

### 2.3 试点形态：脚本/测试级，补真实工具路径覆盖

**形态**：沿用 3c D3——`tests/test_isolation_pilot.py` 的 pytest 试点（Windows 真机跑、
POSIX skip-with-reason，:19-23），不落散装脚本、不接 `BaseTool.ainvoke` / AgentLoop。
5b 在既有 S1–S4 之上补一个**真实工具路径**的复合场景 S5：

- **S5（real-write deadline/terminate/late/lease）**：用真实 `write` 工具 + 大内容
  payload 在 tmp workspace 写入，deadline 设在实际写入完成之前；断言
  `terminated`/`stopped`、返回的 payload 不含成功写入回执、止损后 lease 事件序
  acquire < confirmed < release，并如实记录磁盘上是否留下部分文件（不假设为空）。
  若实测难以稳定命中「写入中途」（本地 FS 写入太快），退而采用**真实工具 + worker
  侧延时驱动**：新增仅测试用的 `probe_slow_write` 探针——先 `time.sleep` 再调用真实
  `write`（注册表按名查找，与 `_run_tool` 同一路径），使 deadline 确定性地落在
  「已派发真实工具、尚未写出」的窗口；**不得用纯 `probe_sleep` 冒充真实工具路径**。
- 保留 S1–S4 原样（3c 已验收，不重写）；S2/S3/S4 仍由 `probe_sleep` 驱动，作为
  **协议层**终止/迟到/lease 保证的回归，S5 负责**真实工具层**的端到端证据。

**端到端证据清单**（5b 验收会逐条核对）：写盘成功与 tmp 边界（S1）、deadline
终止并确认（S2 + S5）、迟到结果不归因（S3a + S5）、毒化拒收（S3b）、lease 顺序
（S4 + S5）、绝对路径被拒（S1 扩展一条：同一临时 workspace 下传绝对路径 →
工具返回 error 且磁盘无越界文件）。

### 2.4 B2.4 前置依赖：复核在前后两个阶段的不同含义

| 维度 | B2.4 前（本批 5a/5b） | B2.4 后（5c 复查） |
|---|---|---|
| 试点开关 | 显式 allowlist + 脚本/测试调用点，零生产 blast radius | 必须核实生产 dispatch 也按 allowlist 门禁，不允许「声明 isolatable 即自动隔离」 |
| 准入执行点 | `ToolRegistry.timeout_capability` 惰性查询 + 试点层 C4/C5 | 追加生产接线处 fail-closed 硬门禁：未过 C1–C3 或未在 allowlist → 回落原执行模式，不得静默分叉 |
| 工具面变化 | 冻结（只审 `write`） | 复查 B2.4 新增/改写的工具与装配路径是否引入新的回调依赖；重跑全注册表 C2/C3 扫描 |
| 时序协议 | 3c 已验收（毒化拒迟到） | 核实 per-call id / deadline / lease 的生产实现不削弱「迟到拒收」；若 B2.4 改了 worker 注入面，C2/C3 事实源须同步 |
| 分叉语义 | 记录在案即可（display/task/todo 留在进程内） | 必须显式裁决这些工具在生产中**继续进程内执行**，不得因为接线而被动进入 worker 后静默丢事件 |

**5c 的前置硬条件**：B2.4 已验收且单独批准；未满足时只交付 5a/5b，5c 不启动，
也不得在文档/发布说明中宣称准入复核已覆盖生产路径。

## 4. 风险与回滚

- **终止不撤销副作用**：deadline 命中时 write 可能已写完或部分写入 tmp 文件。
  缓释：试点 workspace 限定 `tmp_path`（进程退出即由 pytest 清理），报告显式记录
  残留；**禁止**在文档/发布说明写「无副作用」「可回滚」。若未来试点扩大到持久目录，
  此风险必须重新审查。
- **路径保护漏判**：默认写根是 `(".",)`（`legacy.py:149-151`），边界是整棵 workspace
  子树；`~` / UNC / 盘符的判据是历史修复（`legacy.py:238-268`），跨平台行为差异
  必须在 Windows 真机复测。试点不得以 docstring 的旧四目录清单作为安全依据；
  绝对路径越界断言是回归防线。
- **静态扫描的漏检/误报**：别名/反射/`getattr` 可能绕过 C3；`inspect.getsource`
  在打包/动态生成场景下不可用 → fail-closed 会拒绝本来安全的工具。缓解：C4 显式
  allowlist 是执行依据，C3 只是审查辅助；误报走人工审查 + 测试内明确豁免（附理由），
  不得全局关闭扫描。
- **不扩大到 shell**：roadmap §6 #5 已将 shell 延期；试点 allowlist 硬编码 `{"write"}`，
  5b/5c 均不得借「顺手验证」加入任何 shell/远端工具；任何扩大都需新 R-014 方案。
- **B2.4 前置未就绪误启动**：5c 仅在 B2.4 验收后启动；未满足时禁止把脚本级结论
  外推为生产保证。
- **回滚**：每子批独立提交；5a 回退仅恢复纯 effects 准入；5b 回退仅移除试点场景与
  allowlist 开关；5c 回退仅撤销生产门禁复核结论。全程零生产接线（截至 5b），
  回退零生产影响；5c 的回退策略须与 B2.4 的「整体关闭隔离 deadline adapter」一致，
  不得保留部分接线。

1. **shell 工具接入**——延期，不因试点成功顺手扩大（roadmap §6 #5）。

   「拒绝依赖」判定，不实现进度回传协议（B2.3 §6 #7）。
