   不清理、覆盖、回退或提交他人工作；无法区分归属就暂停该文件并协调。提交须另经用户确认。
5. 本计划以当前仓库代码为运行行为的事实依据；主设计文档负责视觉方向，复用评估

## 1. 目标与完成定义

### 1.1 第一阶段：可使用的 MVP

一个新用户或已有用户能按说明启动真实服务、登录、进入工作台、创建或选择会话、
发送文本、看到所配置真实模型的回复，并在刷新后找回已持久化的会话和消息。
发送与流式过程中的错误、连接中断及恢复有明确反馈；键盘、浅/深主题和窄屏可用。
登录、会话和消息的视觉语言追踪 U-A，不能只交付静态样稿。

**MVP 完成须全部满足**：

- 真实后端健康、前端入口可访问，非 mock 登录成功；错误密码和服务故障有可理解提示。
- 创建、切换、刷新恢复会话；列表请求失败不当成空列表新建；普通会话不按标题隐藏。
- 用户发送一条可辨识文本，真实模型回复可见，刷新后用户与助手消息仍归属原会话。
- 发送失败可见，文本和发送期间的新输入不丢失、不串会话；发送中的重复提交被阻止。
- 真实 SSE 连接、流式结果及停止操作经实机验证；断线、重连及失败状态不会冒充成功。
- 深/浅主题各通过 320、768、1440 CSS px 的登录与会话主路径；键盘可达、焦点可见，
  主内容不靠整页横向滚动使用。正文对比度 ≥4.5:1，大号文本 ≥3:1，控件边界及焦点 ≥3:1。
- 自动化、类型检查、lint、隔离构建及实机矩阵通过；文档包括启动、配置、操作、限制和排错。

### 1.2 第二阶段：完整前端

在 MVP 稳定后，按依赖实现统一的导航和令牌、会话高级能力、审批、运行任务、
Trace、工作流、设置与管理、监控，以及具备真实数据契约的研究/策略/因子/RSI 表面。
“完整”指约定范围内的界面能通过真实数据、权限和错误分支的验收；不能仅靠页面存在、
截图或测试替身宣布完成。对缺少后端能力的功能，先输出契约、可见的不可用状态和
后续接入步骤；是否恢复或新增业务后端需单独决策。

### 2.2 阻塞与证据边界

- 隔离后端曾未就绪：Python asyncio 最小探针停在 `socketpair()` 的 `accept()`；
  独立 Node 本机回环探针返回 `EACCES`。本地网络有效策略显示允许，但实际行为不一致；
  现有证据**不能证明**二者有同一根因。
- 后端、浏览器真实交互、真实模型回复**均未验收**；不能把静态预览、mock 或单测当成联调完成。
- 沙箱拒绝连接后不通过其他命令、语言、代理或工具重试同一被拒绝操作。先由用户或
  管理员调整策略或排查，再恢复 P0-2；若仍拒绝，记录阻塞并停止相关动作。
- 工作区有多项其他 agent 的修改和未跟踪文件；本计划不判断全部归属，不做清理。

### 3.2 通用视觉与交互约束

- 中性表面和边框承重；浅色主操作中性黑、深色反转；蓝用于品牌、链接和焦点；
  success/warning/destructive 表达状态，Trace 角色色和 DAG 节点色是语义例外。
- 区分正文、次级信息及辅助信息；禁止用低对比度小字承载关键操作或状态。圆角、
  间距与密度遵循示意的 4px 节奏及 6/8/12px 参考，不要求逐像素复制。
- 每个表面定义 default、hover、focus-visible、disabled、loading、empty、error；
  状态同时用文字/图标表达，不能仅靠颜色。尊重 `prefers-reduced-motion`。
- 桌面多栏，窄屏抽屉/切换而非固定挤压；长会话名、代码、表格和附件不能遮住输入与操作。
- 示例数据只允许在明确标注的开发/测试展示中使用；生产页面分别区分真实空、无权限、
  加载、失败和未接入，不将缺失值补成零或默认成功。

## 5. P0：MVP 详细实施步骤

### P0-1 基线和隔离准备

1. 核对 Git 状态、近期提交、相关文件 diff、stash；登记每项本任务已有改动和未确认归属。
   对共享文件按行审阅，冲突时停止并协调，绝不整体覆盖。
2. 在桌面、窄屏各保存当前登录和会话基线，分别标注明/暗主题、视口、数据类型和日期；
   mock 截图只作视觉基线。保留现有基线，不为消除差异直接重录。
3. 建立单独工作区、会话库、数据目录和构建目录；先确认路径不存在或确属本次专用，
   记录路径、进程 PID 和端口。默认 `npm run build` 会清空/覆盖 `webui/static`，
   不用它验证隔离构建；使用新目录传给 Vite `--outDir`，确认不会影响他人产物。
4. 记录 Node、Python、依赖与项目脚本版本；仅在依赖缺失或清单变更时安装。
   按 [前端 README](../../webui/frontend/README.md) 的实际命令检查启动说明，错误先回填文档再实施。

**验收**：基线与路径清单可重现；工作区和已有进程/产物未被覆盖；所有事实有出处。

### P0-2 解除联调阻塞并启动真实服务

1. 由用户/管理员检查允许本地网络的有效策略与实际 `EACCES` 的差异。不要自行提权、
   修改访问控制或更换工具绕过；政策调整前停止对相同被拒绝连接的重试。
2. 放行后先运行最小本机连接探针，记录通过/失败和环境；失败则停止该批并回报，
   不推断 Python `socketpair()` 的唯一根因。
3. 确认独立工作区与数据路径：用户库由 [user_db.py](../../src/agentnodes/interfaces/api/user_db.py)
   按工作区定位，会话库解析见 [session/db.py](../../src/agentnodes/kernel/session/db.py)；
   同时核对 `AGENTNODES_DATA_DIR`、`AGENTNODES_SESSION_DB`、LLM 配置覆盖和启动参数。
   **单设任一变量不足以证明完全隔离**：启动前逐项确认真实读写位置和是否会读取用户配置。
4. 只在隔离工作区、独立数据/会话库和确认可用端口启动后端；首次管理员密码通过
   受控方式提供，不打印、截图、写入文档或提交。确认进程 PID 和 `/health`；
   再按 README 启动前端并核对代理目标。不要停止、覆盖其他进程或数据库。
5. 后端、前端均就绪后记录实际地址、无敏感信息的健康结果和进程归属。完成验收后只停止
   本批明确启动的进程；专用数据及构建产物是否删除须另行确认。

**验收**：真实 `/health`、前端入口和认证请求可用；所有读写位置、PID 和端口已核验。
**失败处理**：记录最后成功点、错误及环境；不把构建或 mock 结果写成服务已运行。

### P0-3 登录与会话

1. 对照示意迁移登录表单、品牌、主次操作和表面；保持真实认证、注册策略和路由。
   验证空输入、错误密码、网络失败、重复提交及成功跳转；不要泄露密码或 token。
2. 验证会话加载中/空/失败/重试：故障不自动变成新会话；成功空列表才按现有规则初始化。
   验证已有会话恢复、选择、创建、刷新及多标签页切换。
3. 会话列表使用真实返回的数据，普通标题（包括 `test`、`debug`）不应被关键词过滤；
   Study 特殊会话的既有隔离语义单独测试，不因视觉迁移改变。
4. 按 U-A 组织导航、标题栏、会话列表及输入/消息区；窄屏面板互斥且可关闭，桌面偏好
   不被移动视口临时状态覆盖。核对初始化失败与重试期间不会创建重复会话。

**验收**：登录和会话成功/失败状态的组件测试与浏览器操作均通过；刷新后列表和当前会话正确。

### P0-4 发送、流式和恢复

1. 逐条验证文本发送：用户消息、请求返回、SSE 增量、最终助手消息及刷新后服务端历史；
   区分“请求已接受”和“模型生成成功”。
2. 发送中通过按钮、Enter、斜杠自动发送等入口验证不会重复发同一请求；成功后允许下一条。
   验证生成时停止动作与队列的现有语义，避免把排队误标为实时生成。
3. 覆盖网络失败、服务拒绝、限流、模型配置错误、SSE 断开、重连与刷新；错误可见、
   乐观消息不冒充成功，原文本与期间新增输入均保留并归属于原会话。
4. 跨会话/卸载失败时，当前代码只保证文本草稿；对图片在这些情形下先复现并明确保存、
   提示或不支持方案，再按图片能力批次实现，不宣称已有完整附件恢复。
5. 检查 localStorage 不可用/写入失败、快速切换及多请求边界是否造成新增草稿丢失；
   如发现问题，先写能复现用户行为的测试，再做最小修复并显式提示。

**验收**：受影响测试及真实服务场景通过；消息不重复、不串会话、不静默丢弃文本。

### P0-5 视觉验收、真实对话与交付

1. 以真实数据运行深/浅主题 × 320/768/1440 宽度：登录、创建、切换、发送、回复、
   停止、侧栏、右栏、错误态逐项核对；长内容、200% 缩放和键盘导航单独检查。
2. 核对文字/控件/焦点对比度，标注实际测量点和数值；核对 focus、读屏名称及 reduced-motion。
   同时用示意截图比较布局与色彩；视觉可接受但与示意不同的地方记录原因。
3. 在受控环境配置真实模型（允许使用现有授权，但先确认配置读取位置和调用费用）；
   记录发送成功、回复、刷新恢复和模型身份，不记录密钥、认证头或敏感会话内容。
4. 按 §10 全部执行并记录测试、类型、lint、隔离构建和实机结果；失败项必须修复或明确阻塞，
   不降低门槛。更新 README 的安装、启动、登录、模型配置、交互和排错。
5. 输出 MVP 验收表：通过 / 失败 / 阻塞 / 不适用，附证据；仍有任何必选项未通过则
   标记“未完成”，再安排下一次执行，不提前进入“已交付”状态。

## 7. P2：后续完整业务表面

本节为后续路线，不意味着当前恢复已移除的业务域。每项先由产品和后端负责人确认：

### P2-1 Study、Run、策略与因子

1. 分别绘制列表 → 详情 → 可操作项的用户流程及状态机；核实对应 API 是否真实挂载、
   数据来源、分页/筛选、身份与 workspace/session 归属，记录缺口。
2. Study：明确研究任务、轮次、进度、错误及关联会话的数据契约；先有服务与事件，再接列表、
   详情、进度及可用操作；未挂载时明确“不可用”而非空列表。
3. Run：明确它与 DAG workflow run、历史 backtest 的边界；定义创建/查看/取消等允许的
   操作与真实来源后，再做列表、详情、状态、结果和错误。
4. 策略：分别呈现策略、Study、Run 的加载与局部错误；必须有可靠策略↔运行的关联键，
   不能把所有 runs 挂到每个策略；缺指标显示未知而非零。
5. 因子：定义目录/详情/搜索的服务契约和权限；保留 mock 的明确标签直到真实数据接入。
   不以示例因子数量冒充真实目录，不删除已有示例资产。
6. 每个域独立补充契约文档、后端/前端接线测试与真实浏览器验收；若业务域不恢复，
   该域以明确不可用状态交付，不宣称业务功能完成。

### P2-2 RSI 进化视图

1. 与负责人确认信号源、轮次、状态、证据、评分及 Δ 的定义、单位、时间窗口和权限；
   梳理现有 evolution 能力与 API 差距，不能据代码目录存在推断 UI 接口存在。
2. 先设计只读契约与样例 schema，规定缺字段、未采样、错误和过期状态；真实空缺、
   加载失败、无权限必须可区分。
3. 按示意设计信号健康、轮次/闭环阶段、评分及证据流；红黄绿用于健康语义，
   分数变化提供来源和含义。所有数字与状态来自服务端真实字段。
4. 只在操作契约和权限齐备后加入启动/中止/重试等动作；审计副作用及失败恢复。
5. 使用真实数据验证取值、刷新、筛选、权限、空态和响应式；离线 fixture 仅作组件测试。

### P2-3 高级会话、事件投影及 Gen-UI

1. checkpoint / rewind / fork：先定义持久化边界、恢复对象、工作区副作用、并发与权限；

隔离构建须先选一个**此前不存在**、属于本次任务的专用目录，再执行：

| 门禁 | 方法 | 通过条件与证据 |

| 代码局部 | 对应组件、store、API、SSE 测试 | 新行为有可失败的断言；失败与数量记录 |

如发生代码行为变更，实施时遵循 [项目规则](../../.rules/rules.md) 的文档先行和相应验证；

## 11. 风险、回滚和协作

| 风险 | 预防 / 发现 | 回滚或停机边界 |
|---|---|---|
| 与其他 agent 重叠 | 先读状态及逐文件 diff，约定归属 | 暂停该文件并协调；不使用整体覆盖、reset 或清理 |
| 设计全局改色影响 DAG/图表 | 先列 token 消费者；逐页对照两主题和语义状态 | 回退**本批可识别的独立改动**，不回退他人内容；必要时先协调 |
| 服务/构建污染用户环境 | 独立 workspace、数据、库、端口、PID、构建目录；核实所有路径 | 只停止本批启动的指定 PID；不删除或覆盖原数据库/产物 |
| 会话、附件、事件竞态 | 覆盖切换、卸载、失败、重连和幂等 | 停止发布相关批次，保留用户数据和失败证据 |
| 权限/密钥泄露 | 测试用受控账号；秘密不进日志、截图、提交 | 停止暴露路径，按项目安全流程处理；不复制敏感数据 |
| 缺少后端契约或模型授权 | 接口清单、所有者、权限和可用性先确认 | 保持不可用/待接入，不用假成功替代；需用户/负责人决策 |
| 沙箱拒绝本机连接 | 记录原始 `EACCES` 与策略矛盾，由用户/管理员排查 | 不换工具或代理重试同一受拒动作；真实联调继续阻塞 |

每批建议保持可独立识别的变更和验收记录。未经用户确认不提交；若将来需要回滚，
先检查该批是否包含他人后续修改，再由负责人选择安全的定向撤回方式。
