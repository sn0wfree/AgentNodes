## §1 收敛结论（一句话）

**六项决策方向全部存活（无一项被推翻）；但 v1.0 的「验收与机制层」被两轮评审判定不可直接开工**——
R1 验收表含 1 处事实错误（goal.expression）与 1 处不可达口径（42 测试）；W1 机制有 3 个未定义项
（requires 语义 / 装配顺序 / 检查落点）；W4 验收缺 5 件「让循环真转」的事；另发现一条 v1.0 缺失的
**设计原则**（检查信号的通道不可被被检方控制）。

### 元层：一条 v1.0 缺失的设计原则（红队 N4，全员附议）

> **原则七（候选）· 检查信号必须经由被检方不可控的通道产生。**
> 现状：W1 自检靠自报 requires；证据增量门靠自报事件；goal 判据靠自写 evidence；
> 基线与候选分靠同一进程内可被降级的 golden eval——四处同构漏洞不是四个 bug，
> 是缺一条原则。kernel 侧计算 / 进程外持有 / 不可伪造源，三选一。

另两项元发现：(1) **两轴之间存在第三类行为无主**——运行期进程用 file/shell 工具改包内文件，
既非上行 import 也非合法变异，两轴门禁同时失明（理念四需加第四条规则：运行期写盘防线）；
(2) **验收数字必须带来源脚注**（产生该数字的实测命令），否则重演「42/26/17」三处三个数。

## §4 本轮评审修正掉的错误（含 v1.0 文档自身的）

1. **v1.0 D1 依赖链表 `goal.expression | ∅` 行 = 事实错误**（4/4 实证零消费者）。
2. **v1.0 §3.2「latency 全库零采集（grep→0 处）」= 错误陈述**（实测 85 处 elapsed）。
3. **红队「AST 扫 factory body」被分层修正**为「kind 实现模块集双向差集」——原案对全部真实案例漏报。
4. **红队 A7「报错记 0.0 被缓存」部分修正**：缓存路径实测只收成功 metric（分层）；但 `golden_eval.py:196-198` 单任务异常记 0.0 计入均值被理论派亲验证实——**基线污染通道成立，缓存污染通道待验证**（分歧 3）。
5. **红队 A3「语料全量可读」被理论派修正**：golden eval 回放路径 workspace=None → 每任务独立临时目录，read 工具读不到仓库语料；真实暴露面收窄为 shell 工具绝对路径 + 语料随包分发 + seed 确定性——**方向成立、证据链修正**。
6. **理论派 D4「反对」被分层/务实共同驳回**：证据链证明的是验收缺口，不是阶段划分必然空转。
