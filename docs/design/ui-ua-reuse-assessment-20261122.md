> 日期：2026-11-22  
> 状态：评估及实施依据；不代表所有界面或后端能力已实现。  
> 视觉参考：[U-A 三视图示意](../../tmp/mockup/agentnodes-ui-mockup.html)；
> 设计背景：[UI 工作台设计语言](./ui-workbench-design-20261115.md)；
> 令牌方案：[U-A 令牌体系](./ui-a-token-system-design-20261114.md)。

## 1. 结论与边界

现有 React 前端可以采用 U-A 的设计语言，**不需要推倒重建**。保留现有路由、状态、
会话管理、消息、SSE、工作流和认证；逐步替换视觉令牌、页面布局与交互表面。
示意图是静态设计稿：示例数据、按钮和三视图布局不是运行能力的证据。

- **可复用**：逻辑、组件结构或基础设施可继续使用，但不等于已完成实机验收。
- **需改造**：保留可用逻辑，调整外观、布局或接线，并测试已有功能。
- **待接入**：当前缺少已验证的完整数据/操作契约，不展示假数据或可执行假按钮。
- **后端不可用**：当前 API 装配中没有相应历史业务路由；保留代码与入口，清楚提示。

本评估依据当前文件与示意图，不等同于对工作区归属、当前 Git 差异或运行时的完整审计。
其他 agent 的改动必须原样保留；实施前需先核对 Git 状态、近期提交、diff 和 stash，
并协调可能重叠的文件。未经确认不清理、不覆盖、不提交他人的改动。

## 2. 设计语言目标

| 维度 | 目标 | 验收注意 |
|---|---|---|
| 颜色 | 浅色主操作为中性黑，深色反转；品牌/运行标记为蓝，成功、警告、失败使用语义状态色 | 角色色不替代状态文字；图表和轨迹色按语义使用 |
| 表面 | 中性背景、灰阶层级、细边框、有限阴影；用户气泡以墨色透明表面为示意参考 | 工作台文档 §2/§11.2 对浅色气泡另有实心建议；不把两者误写成一致，以示意为基础并以可访问性验收为准 |
| 布局 | 会话、Trace、RSI 共用视觉语言；桌面可采用多栏 | 缺失数据或能力显示明确状态；示意的固定宽度不能直接用于窄屏 |
| 主题 | 保留深色与浅色和用户原有选择 | 两套主题都检查文字、边框、焦点和状态色，不能仅测深色 |
| 密度 | 统一间距、字号、行高、圆角、控件尺寸 | 正文与操作文字应可读，避免示意中的极小辅助字直接用于关键操作 |
| 交互 | 显示 hover、focus-visible、disabled、loading、empty、error 状态 | 键盘可达、可辨焦点、图标按钮有名称；状态不能只靠颜色表达 |
| 动效 | 克制使用，保留必要状态反馈 | 尊重 `prefers-reduced-motion` |

普通文本与背景对比度目标至少 4.5:1，大号文本至少 3:1；控件边界及焦点指示
至少 3:1。所有关键操作在 320、768、1440 CSS 像素宽度下可达且不被固定侧栏遮挡；
不得通过整页横向滚动隐藏主内容。

## 4. 已识别的实施风险

1. **视觉回归面广**：全局 `slate-*` 映射、primary 工具类、工作流节点和图表共同消费
   色值；只改一组变量可能造成按钮文字、边框或状态色不可见。保留旧行为并逐页面核对。
2. **真假数据混淆**：示意数字、因子 mock、Study/Run 空列表和加载失败必须明确区分。
   没有后端数据时显示未知或不可用，不显示零、成功或示例指标。
3. **认证与权限**：Trace 必须使用现有带认证的请求路径；审批必须保留所有权检查、
   一次/永久语义和失败提示，不能因换肤缩减审批安全信息。
4. **响应式与可访问性**：静态示意在窄窗口出现横向溢出；三栏需要适配为可切换面板，
   并测试键盘、缩放、文本对比、焦点、长内容及动效偏好。
5. **资产与构建**：原有 Geist 文件不在前端 public 字体目录；现已替换为系统字体栈。
   默认构建输出会覆盖
   `webui/static`，验证时不要覆盖其他人的产物。
6. **并行修改**：另有 agent 正在工作，Git 状态不明时无法判断文件归属。只在确认差异
   和所有权后修改；对冲突文件先协调，不采用整体覆盖。
7. **运行验收受环境影响**：Git 已可用，本地网络策略已允许；CIM 进程查询失败的原因
   尚未确定。前端单测与静态构建不能替代服务、浏览器和真实 LLM 联调。

## 5. 建议实施批次与完成条件

每批均先检查涉及文件的 Git 差异，遵循先文档后实现；保留其他 agent 的改动。
批次是验收顺序，不代表可以并发修改同一文件。

1. **基线与数据契约**：确认路由、主题、页面状态、受影响组件、当前差异与现有测试；
   在暗/亮主题和桌面/窄屏记录可复现基线。区分 mock、缺接口和真实数据。
2. **令牌与基础样式**：引入中性/品牌/状态语义值，替换失效字体方案；迁移公共基础
   样式，保留主题切换、焦点、状态色和工作流语义。逐主题比较改前/改后。
3. **会话工作台**：重排导航、会话列表、消息、输入和右侧面板；保留会话管理、流式、
   队列、工具、附件和快捷键。窄屏控制侧栏，不牺牲消息与输入区。
4. **审批与 Trace**：修复已有鉴权及原因传递，处理所有已知响应；统一为 U-A 表面。
   Trace 只显示接口真实字段，缺字段明确标记，不伪造回退/分叉。
5. **其他页面**：逐页迁移登录、设置、用户管理、DAG、监控和历史页面；Study/Run
   明示后端不可用，因子库标示示例数据，策略请求失败可见。
6. **RSI**：先确认 API、事件与权限契约，再接入真实轮次、信号、评分与证据。尚无
   数据时仅显示待接入或空态，不生成演示记录。
7. **收口**：执行自动化和真实运行矩阵，记录可用、不可用及阻塞项；更新启动与操作
   说明，不以测试替身或静态构建代替真实验收。

## 6. 验证矩阵

| 层次 | 最小验证 | 需要捕获的问题 |
|---|---|---|
| 前端自动化 | 受影响组件测试、`npm test`、`npm run lint`、TypeScript 检查 | 交互或 API 参数回归、未处理失败、类型错误 |
| 设计 | 暗/亮主题 × 320/768/1440 宽度；正文、控件、焦点对比度 | 水平溢出、遮挡、不可辨文字与焦点 |
| 行为 | 登录失败/成功、会话创建切换、发送/停止、SSE 断线、审批四种选择和失败、Trace 鉴权 | 看似可点击但未生效、状态丢失、错误被吞 |
| 业务状态 | API 404/401/500、无会话、无工作区、部分数据成功 | 失败被显示为零或空、错误数据混入成功数据 |
| DAG | 编辑、保存、运行状态、节点交互及暗/亮主题 | 画布色与状态退化、已有入口丢失 |
| 实机 | 按 [前端启动说明](../../webui/frontend/README.md) 启动后端与前端，在浏览器用真实会话及已配置模型验证 | 构建成功但端到端不可用；不得输出或提交密钥 |

对于视觉基线，先保存双主题的原始对照，再审核 U-A 结果；不能未经审核直接重录
基线掩盖回归。需要隔离构建时使用新的专用输出目录，确认不存在后再生成，不覆盖
`webui/static` 或其他人文件。

## 8. MVP 收敛范围（2026-11-22）

优先交付登录、进入会话工作台、新建或切换会话、发送消息并查看真实回复这一条路径。
登录成功直接进入 Chat；保留原首页及其他路由，不删除或伪装未完成的功能。
登录页和工作台优先采用示意中的中性表面、清晰层次和主操作样式，并保留双主题、
窄屏、错误提示和键盘可用性。
会话列表加载失败时不得将其当作空列表并自动创建会话；应提示失败并重试。
普通会话不因标题包含 `test`、`debug` 等字样被隐藏。
发送失败时保留原始文本草稿，不覆盖发送期间输入的新内容，也不混入其他会话；
提交尚未返回时键盘和按钮均不得重复提交。

验收必须区分：隔离数据的真实后端连通、前端交互、已配置模型的真实回复；测试替身
只能证明接线，不能称为真实模型验收。Study、Run、策略库、因子库和 RSI 的新增
能力及全面视觉迁移暂缓。真实服务启动不得覆盖已有工作区数据或影响其他进程。

本轮已调整登录入口、工作台背景和品牌，并补充会话列表及初始化错误处理的回归测试。
隔离构建和前端测试通过；隔离后端未能就绪。最小 Python asyncio 探针停在 Windows
`socketpair()` 的 `accept()`，原因尚未确定。真实浏览器联调及模型回复仍未验收，
因此不能将 MVP 标为完成。
后续独立的 Node 本机回环探针返回 `EACCES`，执行环境标注可能受沙箱策略影响；
有效策略虽显示允许本地网络，实际连接仍遭拒绝。该证据不足以单独证明 Python
卡住的全部原因，需先解决策略与实际行为不一致的问题。
