# 提示词 × 基因组：概念对映研究

> **问题**：「提示词和 genome 的关系」到底是什么关系？genome 的哪些概念移植到 prompt 域是**承重的**（能指导设计），哪些是**装饰性的**（只是话讲得漂亮），哪些**根本不成立**？
> **快照**：2026-11-17。本轮为**概念轮**：不重复 `提示词基因框架-业界先例调研-20261117.md`（下称「上轮」）的先例地图，聚焦**概念关系本身** + **AgentNodes 代码级对接**。
> **方法**：上轮 45 项先例复用为底座 + 本轮新增外部检索（Lamarckian/Darwinian、文化进化/memetics、表观遗传/Weismann/HGT 隐喻、DNA 存储）+ 本仓库 `genome_proposals.py` / `genome_version.py` / `harness_resolver.py` 代码事实。

## 0. 一句话结论

**「提示词和 genome」不是一个关系，是六种关系共用一个词。** 这六种关系在文献里并行存在、互不引用，混着谈会得出荒谬结论（比如拿「EvoPrompt 的 genome 是搜索表示」去否定「phenome 的 genome 是比较编码」——它们根本不在说同一件事）。

| # | 关系定位 | 一句话 | 代表 |
|---|---|---|---|
| R1 | **prompt 当基因组**（描述性基因型） | 把一条 prompt 编码成离散位点序列，用于**比较与审计** | phenome / DelvePO / PromptGenome / REPROMPT（上轮已详查） |
| R2 | **prompt 当搜索表示**（操作论基因） | genome 只是变异算子的操作对象，服务**单条 prompt 优化** | EvoPrompt / Promptbreeder / APE 系（上轮判别①已拆） |
| R3 | **prompt 当基因探针** | prompt 是 probe（gene），**模型输出**才是 allele，测的对象是模型不是 prompt | PhyloLM（上轮 §3.0 已拆） |
| R4 | **prompt 当复制子/模因** | prompt 在人 / 厂商 / 模型之间**传播与派生**，是文化复制子 | Dawkins 模因论 → LLM 种群文化进化（本轮新证） |
| R5 | **prompt 当转录本** | prompt 是基因组**选择性转录的产物**，基因组是它的上游工件全集 | **AgentNodes 自身架构**（本轮代码级确认） |
| R6 | **基因 ≠ prompt**（同名异物） | AI 域的「基因」还可以是权重片段，与 prompt 无关 | learngenes / GRL（本轮新证） |

**★ 本轮最重要的架构发现（R5）**：在 AgentNodes 里，`prompt` 同时有两重身份——

1. **Tier 1 基因**：`kernel/evolution/genome_proposals.py:41-49` 把 `prompt`（连同 skill / graph_shape / tool_set / compaction）列为**可提案的基因组组件**；
2. **运行时转录本**：`kernel/agent/harness_resolver.py` 按 task_signature **选择性选取** prompt 版本、追加 skill 文档（"只追加，原 prompt 逐字保留"）——装配出的 runtime system prompt 是**转录产物**，不是基因组本身。

⇒ **由此得出本轮对上轮框架最重要的一条修正**：CL4R1T4S 这类「厂商 system prompt 语料」是**转录本观察，不是基因组观察**。我们上轮设计的「prompt 基因序列」实际是把**表达产物**当**基因型**来读——这个错位不是错误，但必须显式声明口径（详见 §4.3）。

## 1. 六种关系的逐一定位

### R1 · prompt 当基因组（描述性基因型）——本项目的主线

上轮已详查（phenome 的 64 loci × 251 等位、DelvePO 的 Loci/Alleles、PromptGenome 的组件型 genome）。本轮只补一个概念判定：

**它的生物学原型是「基因分型」（genotyping）**：把个体映射到一组已知位点上的等位组合。生物学的基因分型服务于**比较**（亲子鉴定、群体遗传、GWAS 关联），phenome/DelvePO 把同一操作搬到 prompt 上——但生物学里位点表来自百年群体遗传学积累，prompt 域的位点表**没有这个积累**，这正是上轮「P2 位点集自动发现」空白的深层原因：**我们在做的事情相当于在 1910 年代做遗传学——染色体理论刚立、图谱未画。**

### R2 · prompt 当搜索表示——目的相反，勿混

上轮判别①已拆清楚：EoT 线的 genome 是**搜索表示**（种群/突变/交叉/适应度），优化「一条 prompt 好不好」，从不回答「两家 prompt 在第 7 个位点上是不是同一个等位」。本轮补充一个概念判定：R2 的生物学原型是**遗传算法的操作论基因**（Holland 1975 的 fixed-length genotype），而 R1 的原型是**分子生物学的结构论基因**。**同一个词「genome」在两条线里差了 60 年学术史**，这就是文献互不引用的原因。

### R3 · prompt 当基因探针——对象错位一层

PhyloLM 把 prompt 当 gene、输出 token 当 allele，树长在**模型**上。生物学原型是**分子标记**（molecular marker / AFLP）：用已知基因做探针，测的是**携带者之间的亲缘**。我们要做的横移（探针不动、测厂商 × 位点矩阵）本质是把「分子标记」换成「形态学性状」——从分子系统发育退回**形态系统发育**（比较解剖学）。这不是降级：形态学性状正是位点表，二者在生物学里各有分工（分子测近缘、形态测远缘与趋同）。

### R4 · prompt 当复制子/模因——本轮新增证据

Dawkins《自私的基因》第 11 章的定义：模因「通过从脑到脑的跳跃在模因池中传播自己，正如基因通过精子/卵子从体到体传播」。prompt 完全符合这个定义：它在人 → README → 语料库 → 另一个厂商的 prompt 之间复制派生（CL4R1T4S 全库就是证据）。

**本轮新证**：LLM 种群的文化进化已有实验框架——
- **Cultural evolution in populations of LLMs**（arXiv [2403.08882](https://arxiv.org/abs/2403.08882)，INRIA flowerssteam，代码开源）【已核实摘要】：多智能体模拟平台，操纵网络结构、人格、社会信息的聚合与变换方式，研究 LLM 种群里文化随代际的漂变。**它的传输媒介就是文本（prompt 级）**——prompt 在这条线里就是**模因**。
- 传播链（transmission chain）实验范式（PIBBSS 的 LLM 合作实验等）已把「一条指令经过 LLM 转述再传给下一个 LLM」做成标准方法。

⇒ **对本项目的意义**：R4 回答了上轮「伪同源陷阱」的**成因**——prompt 语料的演化不是树状的（垂直遗传），是**网状的**（水平传播 + 派生改写）。生物学对应现象是**水平基因转移（HGT）**，原核生物的主要进化方式；对 HGT 主导的数据建系统发育树，正确做法是**网状/网络模型**，树只能当近似。这为上轮自研项 #9（null 树负对照）提供了生物学理论支撑：**树本身就该被怀疑，null 树是量化这份怀疑的工具。**

### R5 · prompt 当转录本——AgentNodes 自身的架构事实

见 §0 与 §4（代码级展开）。这是六种关系里**唯一有生产代码背书**的一种，也是对本项目最有操作性的一种。

### R6 · 「基因」的同名异物——多义性陷阱

**learngenes / Genetic Reinforcement Learning**（arXiv [2306.10225](https://arxiv.org/html/2306.10225v2)）【已核实摘要】：基因 = **神经网络片段**（子网络），可跨代继承，论文明确验证了**拉马克式继承**（获得性状传给后代）。与 prompt 毫无关系。
**EvoAgent**（arXiv [2406.14228](https://arxiv.org/abs/2406.14228)）【已核实摘要】：把**已有 agent 当个体**做突变/交叉/选择生成多智能体系统——「个体」是整个 agent，不是 prompt。
**Fernando 2026《A Synthetic Framework for AI Genome》**【仅标题级，PDF 抓取失败】：标题声称「可遗传架构 · 开放式超级智能体进化」，全文未读，本轮不引用其内容。

⇒ **风险**：检索「AI + genome」会同时命中这三类工作。本项目文档引用时**必须写明用的是哪一种「基因」**，否则审阅者会拿 R6 的定义反驳 R1 的设计（或反之）。

## 2. 概念对映总表

判定分四档：**承重**（直接指导设计决策）/ **部分**（方向对但有条件）/ **装饰**（形似神不似，只可作修辞）/ **失效**（会导致错误结论）。
生物学侧事实凡标【教科书】为领域共识；凡标数为本轮核实的来源。

| 生物学概念 | 教科书定义 | prompt 域对映 | 判定 | 依据 / 条件 |
|---|---|---|---|---|
| **基因 / 位点 / 等位** | 染色体上的功能位置及其取值 | 条款 / 位点 / 取值（上轮 P3） | **承重** | 5 个先例用同套词汇；DelvePO 明写 loci/alleles |
| **基因型 / 表型** | 遗传组成 / 可观测性状 | prompt 文本 / 行为评测分数 | **承重** | 但映射函数是黑盒（见「中心法则」行）；phenome 自曝 68% 方向偏移≠遵守 |
| **突变 / 交叉 / 选择** | 变异源 / 重组 / 适应度筛选 | 重写算子 / 条款重组 / eval 门 | **承重**（限 R2） | 只在优化语境成立；放进 R1 比较语境是装饰 |
| **基因敲除（knockout）** | 定向失活单基因观察表型变化 | 组件消融（PromptPrism 受控敏感性分析） | **承重** | ★ 本轮负发现：**没有任何工作显式用 knockout 框架做 prompt 消融**——PromptPrism 已在 doing，没人把它叫做这个。方法论可整套搬（必要基因↔必要条款） |
| **必需基因 / 非必需基因** | 敲除致死 / 可活 | 消融后 eval 崩 / 不变的条款 | **承重** | 与上轮「无 task gene、超长 gene」lint 规则同构 |
| **最小基因组** | JCVI-syn3.0：531,560 bp / **473 基因**（438 编码 + 35 RNA），由 ~910 基因的母本体删到最小；**约 1/4 编码基因功能未知**（[JCVI 2016](https://www.jcvi.org/media-center/first-minimal-synthetic-bacterial-cell-designed-and-constructed-scientists-venter)、[PMC5710109](https://pmc.ncbi.nlm.nih.gov/articles/PMC5710109)） | 「最小可活 system prompt」：消融出能维持目标行为的条款最小集 | **承重**（方法论级） | ★ 关键对照：连最小生物体都有 **1/4 基因不知功能**照删不误（先删了还能活）——prompt 消融也应允许「不知道这条干嘛的，但删了没坏事」级别的不确定 |
| **保守区 / 超保守元件** | 跨物种序列几乎不变的区域 | 跨厂商共有条款 / 共识序（上轮 P4） | **部分** | bio 的保守性由纯化选择**维持**，prompt 的「保守」可能只是**共同模板抄袭**（R4 网状传播）——必须区分「保守」与「同源」 |
| **非编码 DNA / 假基因** | 不编码蛋白的序列；退化失活的基因拷贝 | 无可测效果的条款 / 死指令 | **部分** | bio 判定 junk 要靠敲除实验；prompt 同理——「没效果」必须是**消融后**的结论，不能是措辞直觉（人类基因组编码区仅 **~1.5%**、基因数 ~19k–20k，[NHGRI](https://www.genome.gov/genetics-glossary/Gene)——「绝大部分序列不承重」在两个域都成立，但**哪些**不承重都只能实验定） |
| **启动子 / 顺式调控元件** | 基因上游的结合位点，决定是否/何时转录 | 条款的位置敏感性；指令优先级层级（system > user > tool，上轮 #36） | **部分** | prompt 对「条款顺序」敏感是实测现象（PromptPrism 句法层）；但 prompt 没有「每个基因配专属启动子」的一一结构——顺序影响是全局的、非局部的 |
| **转录因子 / 反式作用因子** | 结合顺式元件调控其它基因表达的因子 | 运行时注入器（AgentNodes `GoalContinuationInjector`：不改基因组、往装配链里注入因子） | **承重**（AgentNodes 事实） | 反式/顺式区分恰好对上：「基因组工件」= 顺式，「运行时注入器」= 反式 |
| **表观遗传** | 不改 DNA 序列而改变表达、部分可隔代 | 会话上下文 / RAG / 注入内容（不改 prompt 模板而改变行为） | **部分** | 方向对；但表观遗传可**有条件隔代遗传**（Jablonka & Lamb《Evolution in Four Dimensions》四维遗传框架），而会话上下文**不可隔代**（每 session 重置）——除非 RAG 库沉淀，那已是拉马克通道（见下行）。AI 侧已有人做此类比（[Epigenetic Analogies in AI](https://www.researchgate.net/publication/387106179)，【仅摘要级】） |
| **水平基因转移（HGT）/ 转座子** | 非亲代-子代的基因横向转移；可跳跃的序列 | ① prompt 抄袭/派生（CL4R1T4S 语料的成因）② **prompt injection**（外源序列劫持转录机器） | **承重** | ①解释了树模型为何先天不适配（R4）②与 [Instruction Hierarchy 2404.13208](https://arxiv.org/abs/2404.13208)（self/non-self 识别 = 免疫识别）+ [OWASP LLM01](https://genai.owasp.org/llmrisk/llm01-prompt-injection/)（direct/indirect = 垂直/水平感染途径）在防御设计上互恰 |
| **Weismann 屏障** | 体细胞获得性状不写入生殖系 | 「运行期经验不直接改基因组」 | **承重**（但 AI 侧是**有意打破**） | AgentNodes 的对应物是**结构性的**：EvolutionAgent 只能提提案、validation_gate 才能生效（`genome_proposals.py:1-11`）；上轮理念七「检查信号经由被检方不可控通道」就是屏障规则的工程表述。**但 AI 与 bio 恰好相反**：bio 把屏障当铁律，AI 把**打破它当目标**（见拉马克行）。AI 侧同构论述见 [Selection Without a Selector](https://siliconbasedintelligence.com/writing/selection-without-a-selector)（【仅摘要级】） |
| **拉马克 vs 达尔文继承** | 获得性状遗传（bio 中被 Weismann 屏障否决）/ 变异+选择 | 经验直接写回 prompt/skill（拉马克）/ 种群进化选优（达尔文） | **承重**（★ AI 侧拉马克是常态） | learngenes 明确验证拉马克继承可行（R6）；EvoPool（EMNLP 2026 Findings）【仅摘要级】以拉马克视角讨论 prompt 累积增长；**RSI 系统本质是拉马克机**——AgentNodes 的 skill_memory（经验→技能沉淀）就是获得性状写回生殖系 |
| **忠实复制 / 校对酶** | 聚合酶校对+错配修复把残留错误压到每碱基每代 10⁻⁹–10⁻¹¹（DNA 基因组；RNA 病毒无校对，高出数个量级）【教科书】 | prompt 复制**无任何校对机制**——每次经 LLM 转述/网页转载/重排格式都是有损重写 | **失效**（指「prompt 是忠实复制的基因」这一隐含假设） | ★ 对上轮自研项 #10（provenance）的强化：prompt 语料的「同一份」永远只是**声明**，不是机制保证；版本/时间戳/哈希锚点不是锦上添花，是**替代缺失校对酶的唯一手段** |
| **中心法则** | DNA→RNA→蛋白，信息单向流动；**密码子表近乎普适**【教科书】 | G→E→P；装配 prompt→模型→行为 | **部分** | 结构同构；但 **bio 的翻译器（核糖体）是机械且解码表普适**，AI 的「翻译器」（权重）是黑盒且**无普适解码表**——这正是上轮「位点 schema 无共识、必须自研」的生物学对照（自研项 #2/#8） |
| **C 值悖论** | 基因组大小与复杂度不相关 | prompt 长度与能力不相关 | **承重**（修辞性强） | 两侧事实都成立；提醒不要用「token 数」当优化目标 |
| **外显子 / 内含子 / 可变剪接** | 编码段/非编码段/同一基因多种转录产物 | 条件分支指令 / 模板占位符 / 同一 role 不同装配产物 | **装饰** | 形似；prompt 没有对应的剪接机制（装配是**顺序追加**不是**重组**——`apply_skill_set` 只追加不改写），不产生可操作设计 |
| **有性生殖 / 减数分裂** | 二倍体、隐性等位、杂合度 | prompt 域无对应物（单拷贝） | **失效** | prompt 是**单倍体**：没有冗余备份、没有显隐性——一个坏条款立即全量表达。这其实是 prompt 工程**更容易做消融**的原因（无杂合度干扰），也解释了为什么 prompt 突变更接近**单倍体微生物遗传学**（一个突变一个表型，经典遗传学黄金时代的方法）而不是人类遗传学 |

**判定统计**：承重 9 / 部分 6 / 装饰 1 / 失效 2。**承重项全部指向可操作设计**（消融框架、最小基因组方法论、反式注入器、HGT→网状模型、Weismann→验证闸、拉马克→沉淀通道、provenance→校对酶替代）。

## 3. 类比的失效边界（五条，写进框架声明的「不许暗含的假设」）

1. **复制不忠实**。生物基因组的保真度是**机制保证**（校对酶）；prompt 的保真度只有**声明保证**（provenance 字段）。任何「同一模板的两份拷贝」在证据上都只是「两份自称同源的文本」。⇒ 上轮机检清单「每 prompt 的 provenance 四元组」从「好的习惯」升级为「替代校对酶的唯一手段」。
2. **拉马克继承是常态而非禁忌**。生物域拉马克是伪科学（Weismann 屏障），AI 域拉马克是主流设计（Promptbreeder / learngenes / skill_memory 全是获得性状直接写回）。⇒ **用生物学直觉说「经验不该直接改配置」在 prompt 域不成立**；成立的版本是「经验可以写回，但必须过闸」（= AgentNodes 的 validation_gate 结构）。
3. **网状进化主导，树是近似**。prompt 语料互相派生（HGT 状），系统发育**网络**才是正确模型，树只在局部近似成立。⇒ 上轮 null 树负对照获得理论根据；进一步地，家族聚类的报告**不应只给树，应给网**（至少给出「哪些边来自疑似水平传播」的标注）。
4. **表型可及性极端不对称**。生物 fitness 可直接数后代；prompt 行为只能靠 eval 代理，且代理本身可被优化循环猎取（reward hacking）——这正是 AgentNodes 隔离回放 + 包外 holdout 存在的理由。⇒ 上轮「强制度只是代理指标」的更普适表述：**基因型到表型的映射函数是黑盒且可被博弈**。
5. **无普适解码表**。密码子表近乎普适（几乎一切生物共用一套），使「读别人的基因组」无需协商 schema；prompt 域没有这个前提——每家厂商的「密码子」不同，位点 schema 本身就是需要协商与版本化的对象。⇒ 上轮自研项 #2（schema 形式化）不是工程懒散的补课，是这个域**缺失了生物域用了 60 年才标准化**的东西。

## 4. AgentNodes 代码级对接：prompt 住在基因组哪一层

### 4.1 代码事实（全部本仓库实测）

| 事实 | 位置 | 内容 |
|---|---|---|
| prompt 是基因组组件 | `src/agentnodes/kernel/evolution/genome_proposals.py:41-49` | `TIER1_COMPONENTS = {prompt, skill, graph_shape, tool_set, compaction}`——"prompt # role prompt 内容" |
| Tier 0 冻结清单 | 同上 `:31-38` | `budget / stop_policy / state_machine / methodology`——构造时就拒绝提案（fail at source） |
| Tier 2 自改域 | 同上 docstring | `strategy.py` 等研究产物，不经 validation_gate |

| 选择性转录 | `src/agentnodes/kernel/agent/harness_resolver.py:50` | `resolve_harness(task_signature)` 决定"哪版 prompt / 工具集 / 压缩配置"——**按环境信号选基因表达** |

| 装配 | 同上 `:228` | `assemble()` 一次解析 prompt 覆盖 / tool_set / compaction / skill 集 |

### 4.2 对映：AgentNodes 的 G→E→P 与中心法则

```
生物域            AgentNodes
──────            ──────────
DNA 基因组   ≈    Tier 0 冻结工件 + Tier 1 工件全集
                  （genome_version.py 三层快照；prompt 模板是其中一个基因）
转录         ≈    resolve_harness(task_signature)
                  （按 task_signature 选基因：哪版 prompt、哪些 skill——选择性转录）
mRNA 转录本  ≈    装配出的 runtime system prompt
                  （harness_resolver 装配产物；逐段拼接、原模板逐字保留）
翻译器       ≈    模型权重（黑盒、无普适解码表）
表型         ≈    evals/scorecard · goal journal · event_log（P 层）
转录因子     ≈    GoalContinuationInjector（运行时反式注入，不改基因组）
表观修饰     ≈    会话上下文 / RAG（不改模板而改行为；session 级不隔代）
Weismann 屏障 ≈   EvolutionAgent 只能提案 + validation_gate 隔离验证（结构性强迫）
拉马克通道   ≈    skill_memory：运行期经验 → 技能文档 → Tier 1（获得性状写回生殖系）
```

### 4.3 三条直接推论（本轮核心产出）

**推论一 · CL4R1T4S 语料是转录本，不是基因组。**
厂商 system prompt 是「该厂商基因组在某个 surface、某个时点的一次表达」。由此：
- 上轮「伪同源陷阱」（§5.2 #9）有了**架构级根源**：两条转录本相似，可能因为**基因组同源**（抄同一模板），也可能因为**选择压力趋同**（都要礼貌、都要防注入）——就像鲸和鱼的流线型。位点对齐测的是**表达相似性**，不是**基因同源性**；报告口径必须写「对转录本对齐」。
- 上轮 CL4R1T4S 评估的 F3（MiniMax 双路径：线上产品 prompt 与开源模型卡 prompt 零重叠）获得精确解释：**同一物种、不同组织的差异表达**（肝脏和眼睛的 mRNA 互不重叠是常态）。⇒ 框架做跨源对齐时，「同一厂商的多 surface」要标注为**同一基因组的多次转录**，与「不同厂商」是两种不同的比较（前者测表达可塑性，后者测基因组相似性）。
- 上轮机检清单新增一条：**每条 prompt 记录「装配链」字段**（该转录本由哪些基因、在什么 task_signature 下装配而来）。AgentNodes 天然可记录（`assemble()` 的输入即装配链），研究者语料没有装配链，必须显式标「装配链未知」。

**推论二 · AgentNodes 已自带一个 5 位点的基因组 schema，可与上轮框架双层对接。**
位点表应该分两层：
- **工件级位点（染色体级）**：`TIER1_COMPONENTS` 的 5 个组件（prompt / skill / graph_shape / tool_set / compaction）——每个组件是一个"染色体"，`GenomeProposal.change` dict 是它的等位取值，`proposal_id` 保证每次等位变更可追溯，`rollback()` 游标回退 = 版本链回退。
- **条款级位点（基因级）**：上轮框架草案的位点 schema（⟨语义类别, 主体/适用范围, 强制条件集, 原文指针⟩）住在 prompt / skill 工件**内部**。
⇒ 两层是**包含关系**：条款级位点的变异以工件级提案的形式生效（改条款 → 打包成 GenomeProposal → validation_gate）。上轮框架的「演化层（L3 ⑪）」对接点因此从「概念上对接三层基因组」具体化为：**变异算子产出的位点级 diff，序列化为 GenomeProposal 的 change dict**。

**推论三 · 两条写回通道必须显式区分计量。**
AgentNodes 存在方向相反的两条「经验→基因组」通道：
- **闸门通道（Weismann 式）**：经验 → evidence → GenomeProposal（draft）→ validation_gate（隔离 slot + 只读 holdout）→ activate。信号必须经被检方不可控通道（理念七）。
- **拉马克通道（直接写回）**：skill_memory 沉淀、Tier 2 研究域自改（`strategy.py`）——**不过闸**。
两条通道都有存在理由（拉马克通道快、闸门通道可信），但**计量时必须分开**：上一轮机检清单的「回放一致性」「证据指针非空」只约束闸门通道；拉马克通道需要自己的质量门（沉淀的 skill 也要有来源 trace，否则基因组被无声污染且不可审计）。**建议把「skill 沉淀的来源 trace」列为编码层第一版就留的字段**（后补要重做数据——上轮已论证过这类字段必须前置）。
