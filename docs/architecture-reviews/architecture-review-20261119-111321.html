Problem. 发送流程曾把 history、Gateway、Attempt、事件桥与答案落库分散在 router 周边；当前迁移已新增深模块，但调用方切换仍在进行。

Solution. 完成当前 3a.3b 接线与契约核验；把 bridge/persister 保持为 send_turn 的内部实现，不再扩展 router 知识面。

Benefits. locality：流程故障集中；leverage：同一用例可被不同入口复用；tests 穿过一个 interface 验证顺序、终态与事件语义。

Deletion test. 直接删 bridge/persister 会失去事件投递或恰一次落库，不能删；只有所有调用和 patch 锚迁移后，才可按既有 R-014/R-016/R-020 单独清理旧 helper。重点守住历史读取失败不产生半提交 Attempt、STEER 多等待方、单例观察器与 wire 零变化。

Problem. container 与 lazy fallback 都知道如何构造 stateful dependencies，Projector/Store 的共享身份和关闭责任容易漂移。

Solution. 先厘清生产、测试、脚本三类入口，再把资源图的构造与生命周期规则集中；不引入新 DI framework，不盲删 fallback。

Deletion test. 未证明所有非生产入口都创建 container 前，删除 fallback 会让脚本/测试失效；这是“先明确路径、再收敛”，不是无条件删回退。

Problem. AgentLoop 横跨准备、循环、工具、事件与收尾；阶段共享可变 run state，按行数抽文件会把复杂度移到回调。

Solution. 先为生命周期状态和阶段不变量建立局部性；只有存在真实 seam 与多个消费者/可替换 adapter 时才继续下沉。

Benefits. locality：状态转换与失败收尾集中；tests 穿过真实执行路径；leverage：不让调用方了解内部 phase 细节。

约束. 现有 K5 设计明确反对按 500 行阈值机械拆分。先保同步/异步 parity、hook 顺序、deadline 与事件契约；若没有独立行为和消费者，就保持现状。

Problem. router 的 active map 与 kernel registry 都保存 runner 相关状态；是否重复尚需核对同一 run 的注册、终态和清理路径。

Solution. 先画出两个 registry 的消费者与生命周期；若确实存同一状态，再局部化 execution record 与 owner 可见性元数据。

Benefits. locality：清理和终态由单一 owner 管理；tests 可验证 TTL、越权隐藏与控制操作的一致性。

Deletion test. 不能直接删任一 registry：kernel runner 查询与接口 owner/TTL 信息各有责任。先证实重叠，再决定是否收敛。
