Problem. `register()` 为每个容器注册 `atexit` 回调；`close_all()` 只清 `_REGISTRY`。回调仍持有容器引用，测试 reset / 多次 app 构造后对象无法回收。

Evidence. 只读 weakref 探针执行 `register → close_all → del → gc.collect` 后仍观察到对象存活；当前 31 个定向测试未覆盖该生命周期后置条件。

Wins. locality：关闭与释放归同一生命周期；tests 覆盖用户可观察的资源回收；避免测试/长进程累积已关闭对象。

建议。 先增加可重复的 weak-reference 行为测试，再以最小改动让 close/reset 释放回调持有；验证 close 恰一次、进程退出兜底仍有效。此处是 M12 后续修正，不需要重做 M12 的组合根形状。

Problem. 路由与 kernel 都保存活跃 runner 相关状态，状态存储、结束清理与控制入口可能分叉。

Solution. 先逐项核对注册、状态查询、pause/resume、TTL/清理与 owner 过滤；后决定是互补记录还是重复状态。

Wins. locality：生命周期转移可定位；tests 穿过真实 HTTP 入口；owner 授权继续留在 interfaces。

约束。 已有 M13 独立审查项；不要把 API owner 授权搬入 kernel，也不要在未证明状态重复前合并 registry。

建议下一步：由低风险、可验证项开始

  1. 先闭合 M12 生命周期引用释放。 为 `close_all` / `unregister` 补弱引用回收与关闭次数行为测试；实施最小修正后，跑 M12/API 生命周期测试、batch_gate、架构图同步。
  2. 然后做 M13 只读审查。 对照 router 与 kernel 两个 Workflow registry 的消费者、状态字段、终态清理、并发访问与 owner 过滤；出独立 R-014 方案，不和 4c 混提。
  3. 4c 继续分阶段。 B2.1 已完成且只有准入声明；B2.2 worker/IPC 是首次引入真实执行 seam，应先做方案和平台测试，再逐阶段批准。POSIX 验证在跨平台生产启用前完成，shell 暂缓。
  4. 删除继续等待前置。 旧聊天队列 / 3a.4 需完整正式版本周期和独立审批；`seq_generator` 单独 R-014 删除批；OptionsPricingTool 与 hooks 保留。
  5. 避免全仓重构。 四层方向门禁为零违规；本轮没有证据支持合并 AgentLoop、GraphEngine、Workflow、Swarm 或引入通用 registry/DI 框架。
