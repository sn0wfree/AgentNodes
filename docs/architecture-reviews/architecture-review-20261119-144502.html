Problem. 两个入口仍分别编排一次发送；`/send_async` 路由负责预检、Attempt 与事件顺序，再走旧 helper。

Solution. 核对它是否属于已批准的 3a 目标；若是，单独完成该入口迁移并保持 HTTP 响应与 SSE 契约。

Wins. locality：顺序约束集中；leverage：两入口复用一处实现；tests 穿过同一 seam。

风险与验收。 不能只删重复代码。保住严格历史失败不半提交、Attempt 终态、事件顺序、响应形状与 STEER 行为；用路由契约网和 send_turn 用例共同验证。
Deletion test. 直接删路由逻辑会丢失 `/send_async` 仍承担的行为；先把完整行为迁入，再删除旧路径，复杂度才真正消失。

Problem. 生产 container、dependency fallback、router cache 各自承担部分身份与生命周期规则；router cache 缺少明确 close。

Solution. 按已落库 M12 方案先统一资源所有权与 close 规则，保留真实存在的测试、脚本入口，不盲删 fallback。

Wins. locality：构造与 close 可一处核验；leverage：多入口复用资源图；identity 与释放行为可定向测试。

待裁决。 M12 仍未批准：确认是否接受方案形态、子批 1–4 范围、router cache close 时机，以及 lifespan 是否同批补齐。不要把本报告当成代码变更授权。

建议下一步：按风险与前置排序

  1. 先澄清 send_async 的迁移边界：现有 3a 记录称 send-turn 接线已完成，但代码走查发现 `/send_async` 仍有路由侧编排。先判断它是否有意保留；若非有意，写一个独立 R-014 子批方案，列出契约与回滚点。
  2. 随后裁决 M12：四项问题是资源所有权方案的必要输入；批准后按子批独立提交，先不删除 fallback 或旧名。
  3. 低风险一致性清理：examples 有 10 处失效 `agentnodes.core.*` import，`extension-points.md` 仍提及不存在的 hooks 文件。选择更新还是归档后再处理；不要与架构迁移混提。
  4. 独立退役批：`seq_generator.py` 有既定退役证据但仍需 R-014、四触点同步和短公告；OptionsPricingTool 因注册、预设、UI、文档承诺而保留；kernel/hooks 因真实运行消费者与扩展承诺而保留。
  5. 高风险隔离生产化：4c 已决定 B2.1→B2.5 分阶段，但尚未开始；POSIX 在跨平台生产启用前验证，首个试点限定临时工作区 `file_write`，shell 暂缓。

Top recommendation

先核对 `/send_async` 是否漏在 send-turn 迁移之外
